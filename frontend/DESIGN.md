## 0. 이 앱이 지향하는 인상

**"인쇄물처럼 단정한 흑백. 색은 의미가 있을 때만."**

| | |
|---|---|
| 무드 | **무채색 라이트** — 흰 배경 + 검정 강조 |
| 브랜드 | 색 없음. 검정~회색 명도 계단으로 위계를 만듭니다 |
| 모션 | 절제해서. 단, **좌석·결제 화면은 더 빠르게** |
| 색의 역할 | 🔴 **붉은색만** 씁니다 — 되돌릴 수 없는 동작 |
| 발광(glow) | 쓰지 않습니다. 그림자와 테두리로만 층을 만듭니다 |
| 예외 | 공연 포스터·포토카드 아트는 서로 구분돼야 해서 색을 유지 |

### 판단 기준 3가지

새 화면을 만들 때 이걸로 자문하세요.

1. **구분되는가** — 스크롤할 때 어디서 어디까지가 한 덩어리인지 보이는가?
2. **다음 행동이 보이는가** — 이 화면에서 가장 중요한 버튼이 하나로 읽히는가?
3. **되돌릴 수 없는 건 붉은가** — 로그아웃·탈퇴·취소가 일반 버튼과 같아 보이지 않는가?

## 1. 색

모든 색은 [`src/styles/index.css`](src/styles/index.css) 의 `@theme` 에 있습니다.
**컴포넌트에 색을 하드코딩하지 마세요.** (`bg-[#7C3AED]` ❌)

### 표면 — 겹칠 때 한 단계씩 올립니다

```
canvas      L 0.975  페이지 배경 (아주 연한 회색)
surface-1   L 1.000  카드 · 헤더 (순백)   → .surface
surface-2   L 0.965  카드 위의 요소       → .surface-2
surface-3   L 0.930  그 위               → bg-surface-3
surface-glass        헤더/하단바 (반투명 + 블러)
surface-ink          검정 영역 (홈 히어로) — 안의 글자는 자동으로 흰색
```

캔버스를 아주 연한 회색으로 두고 카드를 순백으로 둡니다. 그래야 테두리가
얇아도 카드가 떠 보입니다. 캔버스를 완전한 흰색으로 만들면 카드가 사라집니다.

카드 안에 카드를 넣을 땐 반드시 한 단계 올리세요. 같은 단계면 경계가 사라집니다.

### 글자

```
text-ink         본문 (기본)
text-muted       보조 설명
text-subtle      메타 정보 (날짜, 개수)
```

### 브랜드 · 보조

Tailwind 관례대로 **번호가 크면 어둡습니다.** (다크 시절과 반대입니다)

| 토큰 | 어디에 |
|---|---|
| `brand-50` ~ `brand-200` | 밝은 배경·칩 (`Card tone="brand"`, `Button soft`) |
| `brand-500` | 보조 아이콘 |
| `brand-600` ~ `brand-700` | 주 버튼 배경, 강조 텍스트 |
| `brand-900` ~ `brand-950` | 검정 — 배지 채움, 히어로 배경, 선택된 좌석 |

> **밝은 값을 흰 배경 위 글자에 쓰지 마세요.** 글자는 `600` 이상,
> 배경은 `200` 이하가 기본입니다. 검정 영역 안에서는 반대로 뒤집습니다.

### 🔴 의미 색상 — **가장 중요한 규칙**

| 톤 | 언제 | 컴포넌트 |
|---|---|---|
| **danger** | **되돌릴 수 없는 동작** | `Button variant="danger" \| "danger-ghost"`, `ListRow danger`, `Card tone="danger"`, `Badge tone="danger"` |
| warning | 하지 않으면 문제가 생길 일 | 얼굴 미등록, 마감 임박 |
| success | 완료된 것 | 예매 완료, 당첨, 선택 가능 좌석 |
| info | 중립 안내 | 오픈 예정 |

**되돌릴 수 없는 동작 목록** — 이 중 하나라면 무조건 붉은 계열 + 확인 모달:

- 로그아웃 · 회원 탈퇴
- 예매 취소 · 대기 신청 취소
- 등록된 얼굴 삭제
- 판매 내리기

```tsx
// ❌ 일반 버튼과 구분이 안 됨
<Button variant="ghost" onClick={logout}>로그아웃</Button>

// ✅ 붉은 테두리 + 확인 모달
<Button variant="danger-ghost" leftIcon={<LogOut size={17} />} onClick={() =>
  open('common/confirm', { title: '로그아웃할까요?', danger: true, onConfirm: logout })
}>
  로그아웃
</Button>
```

여러 개가 모이면 **"위험 구역"** 으로 한 구획에 몰아넣습니다 ([SettingsPage](src/pages/SettingsPage.tsx) 참고).

### 색을 쓰는 곳은 딱 세 군데

| 예외 | 토큰 | 왜 |
|---|---|---|
| 되돌릴 수 없는 동작 | `--color-danger` | 사고를 막는 신호 |
| **좌석 상태** | `--color-seat-*` | 가용성은 색이 가장 빠른 신호 |
| 포토카드 등급 | `--color-rarity-*` | 카드끼리 구분돼야 함 |

```css
/* 좌석 — 이 다섯 줄만 고치면 좌석맵·범례·선택바가 함께 바뀝니다 */
--color-seat-available: oklch(0.63 0.16 152); /* 초록 — 고를 수 있음 */
--color-seat-selected:  oklch(0.16 0 0);      /* 검정 — 내가 고른 자리 */
--color-seat-held:      oklch(0.76 0.15 78);  /* 노랑 — 다른 사람이 결제 중 */
--color-seat-sold:      oklch(0.84 0 0);      /* 회색 — 판매 완료 */
--color-seat-blocked:   oklch(0.91 0 0);

/* 등급 — 이 세 줄만 고치면 테두리·뱃지·글자색이 함께 바뀝니다 */
--color-rarity-normal:  oklch(0.6 0.15 152);  /* 초록 */
--color-rarity-rare:    oklch(0.6 0.16 250);  /* 파랑 */
--color-rarity-special: oklch(0.58 0.21 18);  /* 붉은계열 */
```

**화면 코드에 색을 직접 적지 마세요.** 좌석은 `SEAT_FILL`, 등급은 `RARITY_STYLE` 테이블을
거쳐서만 씁니다. 그래야 색을 바꿀 때 한 곳만 고치면 됩니다.

> ⚠️ SPECIAL 의 붉은색과 `--color-danger` 는 **다른 색**입니다.
> 등급 색을 danger 와 같게 맞추지 마세요 — 카드가 위험 신호처럼 보입니다.

## 2. 그림자와 발광

검은 배경 위의 검은 그림자는 보이지 않습니다. 대신 **위쪽 테두리 하이라이트**로 면을 분리합니다.

| 유틸리티 | 용도 |
|---|---|
| `edge-light` | **카드 기본값.** 위쪽 테두리에 얕은 빛 + 아래 그림자 |
| `shadow-pop` | 모달 |
| `shadow-glow` / `shadow-glow-sm` | 브랜드 발광 |
| `shadow-glow-danger` | 위험 강조 |

### 🚫 발광은 기본적으로 쓰지 않습니다

버튼 hover, 카드 hover, 입력 포커스, 탭 인디케이터, 단계 표시 — 전부 **발광 없이**
테두리 색과 배경 단계로만 반응합니다.

발광이 허용되는 곳은 지금 둘뿐입니다.

1. **선택된 좌석** — 수백 개 중 내가 고른 것을 찾아야 하므로 (SVG 필터, 약하게)
2. **1분 남은 선점 타이머** — 놓치면 좌석을 잃으므로

> 화면 여기저기가 빛나면 "무엇이 중요한지"를 알 수 없게 됩니다.
> 새 발광을 추가하고 싶다면 위 둘만큼 급한 일인지 먼저 따져보세요.

> 이 유틸리티들은 `@theme` 의 `--shadow-*` 가 아니라 **`@utility`** 로 정의돼 있습니다.
> `--shadow-*` 네임스페이스는 색 치환 로직 때문에 유틸리티가 생성되지 않는 경우가 있어서
> `hover:shadow-glow` 같은 변형까지 확실히 도는 `@utility` 를 씁니다.

---

### 예외 — 포토카드의 빛 반사

포토카드 **상세 화면 한 장**만 표면에 사선(`/`)으로 빛이 스칩니다.
실물 카드를 기울일 때 반사되는 그 느낌이고, 이 서비스에서 카드가 "물건"이라는
유일한 촉감입니다. (`features/nft/components/PocaShowcase.tsx`)

지켜야 할 선:

- **목록에는 절대 넣지 않습니다.** 12장이 전부 반짝이면 아무것도 특별하지 않습니다
- **무한 루프 금지.** 들어왔을 때 한 번, 그리고 **누를 때마다** 한 번 훑고 멈춥니다
- 카드를 3D 로 기울이지 않습니다 — 빛만 지나갑니다
- 발광(glow)이 아니라 **반사**입니다 — 흰색 반투명 띠, 주변으로 빛이 번지지 않습니다
- `prefers-reduced-motion` 이면 정지 상태로 둡니다

## 3. 모션

### 강도 기준

| 화면 | 정책 |
|---|---|
| 일반 화면 | 진입 애니메이션 + 리스트 순차 등장 + 상태 전환 |
| **좌석 선택 · 결제** | **지연을 만드는 애니메이션 금지.** 속도가 곧 UX |
| 완료 · 당첨 | 체크 표시가 스프링으로 나타나는 정도. **축포·파티클은 쓰지 않습니다** |

**무한 반복 애니메이션은 기본적으로 금지입니다.** 계속 움직이는 것이 화면에 있으면
시선을 계속 뺏기고, 정작 상태가 바뀌었을 때 눈치채지 못합니다.
예외는 `LiveDot`(실시간 폴링 중), `Skeleton`(로딩 중), 1분 남은 타이머뿐입니다.
모두 "지금 무언가 진행 중"이라는 정보를 담고 있습니다.

### 지속시간 — [`shared/lib/motion.ts`](src/shared/lib/motion.ts) 에서만 가져옵니다

```ts
DURATION.quick  0.14s   즉각 반응 (호버, 퇴장)
DURATION.base   0.24s   기본 (진입, 전환)
DURATION.slow   0.36s   강조 (완료 화면)
SPRING                  위치·크기 이동 (탭 인디케이터, 선택 표시)
```

화면마다 duration 을 새로 적으면 "이 화면만 느리다"는 인상이 생깁니다.

### 준비된 패턴

| 도구 | 용도 |
|---|---|
| `<PageTransition />` | 라우트 진입 (레이아웃에 이미 적용됨) |
| `<Stagger>` / `<Stagger.Item>` | 목록 순차 등장 |
| `<AnimatedNumber>` | 금액·잔액이 굴러 올라감 |
| `<LiveDot />` | 실시간 갱신 중 (좌석·구역) |
| `layoutId` | 탭/선택 표시가 미끄러져 이동 |

### ⚠️ 페이지 전환에 `AnimatePresence` 를 쓰지 마세요

`mode="wait"` 는 이전 화면의 exit 이 끝나야 새 화면을 붙입니다.
**한 번이라도 exit 이 끝나지 않으면 네비게이션이 그대로 멈춥니다.**
티켓팅 앱에서 화면이 안 넘어가는 건 치명적이라, 나가는 연출을 포기하고
[`PageTransition`](src/shared/components/common/PageTransition.tsx) 은 **진입만** 애니메이션합니다.

### 접근성

`prefers-reduced-motion` 을 반드시 존중합니다.

- CSS 애니메이션 → `index.css` 의 미디어 쿼리가 자동 처리
- `motion/react` → `useReducedMotion()` + `reduceIfNeeded()` 사용

---

### 페이지 전환에 transform 을 쓰지 마세요

`transform` 이 걸린 요소는 자손 `position: fixed` 의 **기준(containing block)** 이 됩니다.
페이지 래퍼에 `y: 10 → 0` 같은 이동을 넣으면, 전환이 도는 0.24초 동안
하단 고정 버튼(`BottomBar`)이 뷰포트가 아니라 **문서 아래쪽**에 붙어 한 번 튑니다.
좌석·결제 화면에서 이건 그냥 버그로 보입니다.

그래서 `PageTransition` 은 **페이드만** 합니다. 같은 이유로 화면 전체를 감싸는
래퍼에 `scale`·`translate`·`filter` 를 넣지 마세요.

### 하단 네비게이션 — 지금 어디인지 색 없이 보여주기

무채색이라 회색 농도 차이만으로는 어느 탭이 켜졌는지 잘 안 보입니다.
활성 탭은 **아이콘 뒤에 채워진 검은 알약**을 깔고 아이콘을 흰색으로 뒤집습니다.
라벨은 `font-bold`, 비활성은 `font-medium`.

- 네비 높이 `--spacing-nav`(4.75rem), 아이콘 25px — 엄지로 누르기 편한 크기
- 알약은 `layoutId="nav-active-pill"` 로 탭 사이를 미끄러집니다 (위치가 이어져 보임)

### 폭죽은 한 흐름의 끝에서 한 번만

`<Confetti />` 는 예매 완료 화면 한 곳에서만 씁니다.
canvas 한 장에 그리고, 다 떨어지면 스스로 정리합니다. 무채색입니다 —
폭죽만 알록달록하면 그 화면만 다른 앱처럼 보입니다.
`prefers-reduced-motion` 이면 아예 렌더하지 않습니다.

### 하단 고정 여백 — `pb-safe` 는 padding-bottom 을 덮어씁니다

`.pb-safe` 는 `padding-bottom: env(safe-area-inset-bottom)` 이라
`pb-8 pb-safe` 처럼 같이 쓰면 **pb-8 이 무시되고** 버튼이 화면 맨 아래에 붙습니다.
노치가 없는 안드로이드에서는 여백이 아예 0 이 됩니다.

여백이 필요한 곳은 한 번에 계산하세요.

```
pb-[calc(2rem+env(safe-area-inset-bottom))]
```

## 4. 컴포넌트

새로 만들기 전에 [`src/shared/components/ui/`](src/shared/components/ui) 를 먼저 보세요.
변형이 필요하면 **컴포넌트 안의 variant 테이블에 한 줄** 추가합니다. 비슷한 컴포넌트를 새로 만드는 건 금지입니다.

| 컴포넌트 | 핵심 |
|---|---|
| `Button` | `primary` `secondary` `soft` `ghost` **`danger`** **`danger-ghost`** × `sm/md/lg`, `loading` |
| `IconButton` | 아이콘 전용. `label` 필수 (스크린리더) |
| `Input` | 라벨·힌트·에러·아이콘 한 세트. 포커스 시 테두리 강조 |
| `Card` | `tone` = `default` `brand` `warning` `danger` `success` |
| `ListRow` | 설정/메뉴 한 줄. `danger` 지원 |
| `Badge` / `LiveDot` | 상태 라벨(`size` sm/md) / 실시간 표시 |
| `BannerCarousel` | 홈 상단 광고·이벤트 슬라이더 (`features/banner`) |
| `Segmented` | 탭. 인디케이터가 미끄러짐. 제네릭이라 값 타입이 좁혀짐 |
| `Stepper` | 예매 단계. 연결선이 채워짐 |
| `SectionTitle` | **구획 제목.** 앞에 브랜드 막대 |
| `AnimatedNumber` | 숫자 롤업 |
| `Modal` / `ConfirmModal` | 바텀시트·다이얼로그. `danger` 면 붉은 띠 + 경고 아이콘 |
| `PosterImage` / `PocaArt` | 이미지 없을 때 시드 기반 그라데이션 |
| `Skeleton` / `SkeletonList` | 로딩 자리 |

### 구획 나누기 — "구분이 안 된다"의 해법

카드만 쌓으면 스크롤할 때 전부 같은 덩어리로 보입니다.

```tsx
<section>
  <SectionTitle description="한 번 실행하면 되돌릴 수 없어요">위험 구역</SectionTitle>
  <Card tone="danger" padded={false} className="divide-danger/20 divide-y overflow-hidden">
    <ListRow danger ... />
  </Card>
</section>
```

- `<SectionTitle>` 로 구획을 열고
- 섹션 사이는 `space-y-6` 이상
- 목록은 `Card padded={false}` + `divide-y` 로 한 덩어리로 묶기

### 모달에는 장식선을 두지 않습니다

상단 띠·좌측 강조선처럼 **한쪽에만 있는 선**은 모달마다 달라 보이게 만듭니다.
위험한 동작이라는 신호는 선이 아니라 **내용과 버튼**으로 전합니다
(붉은 아이콘 + `Button variant="danger"`).

### 목록이 비어 있는 동안엔 도는 걸 보여주세요

스켈레톤만 깔면 "레이아웃이 깨진 건가?" 로 읽히는 경우가 있습니다.
목록(공연·티켓·포카)에는 `<Loading label="..." />` — 스피너와 문구를 함께 씁니다.
화면 전체가 비어 있을 땐 `<PageLoader />`, 이미지 자리처럼 크기가 정해진 곳만 `Skeleton`.

### 폼은 필수/선택을 먼저 보여줍니다

`<Input showRequirement required />` 이면 라벨 옆에 붉은 `*`, 아니면 "선택" 칩이 붙습니다.
검증 규칙은 화면이 아니라 **모델의 테이블**에 둡니다 (`SIGNUP_FIELDS`).
항목을 늘릴 때 화면을 고치지 않아도 되고, 규칙이 한 곳에 모입니다.

에러는 **한 번 건드린 항목부터** 보여주세요. 첫 글자에 빨간 글씨가 뜨면 혼나는 느낌이 듭니다.

## 8. "AI가 만든 티" 나지 않게

생성형 도구로 UI 를 만들면 반복적으로 나오는 클리셰가 있습니다.
개별로는 멀쩡해 보이지만 한 화면에 모이면 **"어디서 본 템플릿"** 이 됩니다.

### 하지 않는 것

| 클리셰 | 왜 문제인가 | 대신 |
|---|---|---|
| **그라데이션 텍스트** (제목·이름에 보라→청록) | 가장 흔한 생성형 UI 표식 | 단색 + 굵기로 위계 |
| **배경 라디얼 글로우 블롭** | 랜딩페이지 템플릿 특유의 인상 | 단색 배경 |
| **모든 상호작용에 발광** | 중요도 구분이 사라짐 | 테두리·배경 단계로 반응 (2장) |
| **무한 반복 광택/스캔라인** | 정보가 없는데 계속 움직임 | 정지된 홀로그램 결 |
| **축포·파티클** | 두 번째부터는 방해 | 체크 아이콘 하나 |
| **`pulse` 남발** | 다 급하면 아무것도 안 급함 | 진짜 급한 것만 (타이머) |
| **모든 모서리가 `rounded-2xl` 이상** | 물렁해 보이고 위계가 없음 | 아래 반경 스케일 |
| **뱃지 도배** | 카드마다 3개씩 붙으면 안 읽힘 | 카드당 최대 1개 |
| **카드 왼쪽 세로 네온 띠** | 목록이 형광펜 칠한 것처럼 보임 | 상태는 뱃지로 |
| 느낌표 남발, "✨ 완벽해요!" 류 문구 | 과장된 톤 | 담담한 서술체 |

### 반경 스케일

크기가 다르면 반경도 달라야 합니다. 전부 같으면 위계가 사라집니다.

```
rounded-md    뱃지
rounded-lg    작은 버튼, 아이콘 칩, 포토카드
rounded-xl    카드, 기본/큰 버튼, 입력
rounded-2xl   모달·바텀시트만
rounded-full  아바타, 상태 점, 타이머
```

### 마이크로카피

- 담담한 존댓말. `~했어요` / `~해 주세요` 정도
- 느낌표는 화면당 0~1개
- 이모지는 UI 에 쓰지 않습니다 (아이콘은 lucide-react)
- 사용자가 한 일은 사실만: "예매가 완료되었습니다" (○) / "축하합니다! 예매 성공! 🎉" (×)

### 자문

새 화면을 다 만든 뒤 스스로 물어보세요.

> **이 화면에서 움직이는 것이 몇 개인가?**
> **빛나는 것이 몇 개인가?**
>
> 둘 다 0~1개가 정상입니다.

## 9. 브랜드 — 티캣

**티캣** = 티켓 + 캣. 로고와 마스코트는 **티켓 한 장의 위쪽 두 귀퉁이를 고양이 귀로 세운** 형태입니다.
아래쪽에는 티켓 절취선이 있어서, 고양이면서 티켓인 것이 한눈에 읽힙니다.

| 자산 | 위치 | 용도 |
|---|---|---|
| 앱 아이콘 | `public/icons/logo.svg` | 브라우저 탭, PWA |
| `<CatMascot>` | `shared/components/ui/CatMascot.tsx` | 빈 상태, 완료 화면, 에러 화면 |
| `<Logo>` | 같은 파일 | 마크 + 워드마크 (로그인/가입 상단) |

### 표정 (mood)

| mood | 언제 |
|---|---|
| `neutral` | 기본 (로그인 유도 카드 등) |
| `happy` | 예매 완료, 당첨 |
| `sad` | 빈 목록, 404, 에러 화면 |
| `sleep` | 준비 중인 기능 |

```tsx
<EmptyState mood="sad" title="예매한 티켓이 없어요" />   // 아이콘 대신 마스코트
<EmptyState icon={Search} title="검색 결과가 없어요" />   // 아이콘을 주면 아이콘
```

새 표정이 필요하면 `CatMascot.tsx` 의 `Face` 함수에 분기 하나만 추가하세요.

이미지가 아니라 SVG 라 번들이 늘지 않고, 색이 브랜드 토큰을 따라갑니다.
**마스코트에 3D·그라데이션·반짝임을 붙이지 마세요** (8장).
빈 화면·완료 화면처럼 **여백이 넉넉한 곳에만** 씁니다. 목록 항목마다 넣으면 유치해집니다.

## 10. 홈 히어로 — 검정/하양 경계

홈은 상단이 검정, 아래가 흰 배경이고 **배너가 그 경계에 걸쳐** 내려옵니다.

```
┌───────────────┐
│ ███ 검정 ████ │  상단바 (로고 · 포도알)
│  ┌─────────┐  │
│  │  배너   │  │  4:3
│  ├ ─ ─ ─ ─ ┤  │  ← 경계 = 배너 높이의 90%
│  └─────────┘  │
│ ░░░ 하양 ░░░░ │  카테고리 원형 버튼 · 목록
└───────────────┘
```

### 경계는 JS 로 재지 않습니다

`styles/index.css` 의 `:root` 에 배너 크기를 CSS 로 계산해 둡니다.

```css
--banner-width: calc(min(100vw, 40rem) - 2rem);  /* 레이아웃 최대폭 - 좌우 여백 */
--banner-height: calc(var(--banner-width) * 3 / 4);
```

검정 배경판의 높이는 이 값으로 구합니다.

```
env(safe-area-inset-top) + 헤더 높이 + 배너 위 여백 + 배너 높이 × 0.9
```

`ResizeObserver` 나 `useState` 로 높이를 재면 첫 렌더에 경계가 잘못 그려지고
회전·주소창 변화 때마다 깜빡입니다. CSS 로만 두면 그런 일이 없습니다.

### ⚠️ 배너 비율을 바꾸면 두 곳을 함께 고쳐야 합니다

1. `BannerCarousel` 의 `aspect-[4/3]`
2. `--banner-height` 의 `* 3 / 4`

한쪽만 바꾸면 경계가 배너 위/아래로 어긋납니다.

### 검정 영역 안의 글자

`.surface-ink` 를 쓰면 배경이 검정이 되고 글자색이 흰색으로 바뀝니다.
그 안에서는 밝기 규칙이 반대입니다.

- 마스코트·로고: `<Logo invert />` / `<CatMascot invert />`
- 테두리: `border-white/25`
- 보조 글자: `text-white/70`

## 11. 배포

```bash
npm run build      # → dist/
npm run preview    # 빌드 결과를 로컬에서 그대로 확인 (배포 전 필수)
```

`npm run dev` 로 잘 돌아도 배포본이 깨질 수 있습니다. **배포 전에 반드시 `npm run preview` 로 확인**하세요.

### 백엔드가 없는 동안 — 배포본도 목업으로 돕니다

`.env.production` 의 `VITE_USE_MOCK=true` 입니다.

이걸 `false` 로 두면 **배포한 사이트에서 로그인·공연 조회가 전부 실패합니다.**
개발 서버의 `/api` 프록시는 배포 환경에 없어서, `/api/...` 요청이 정적 호스팅으로 가
`index.html` 이 돌아오기 때문입니다.

백엔드가 붙으면:

1. `.env.production` 의 `VITE_USE_MOCK=false`
2. `VITE_API_BASE_URL` 을 실제 API 주소로 (같은 도메인이면 `/api` 유지)
3. `src/mocks/` 폴더 삭제 + `main.tsx` 의 `setupMocks()` 블록 삭제

> 목업이 켜진 배포본은 **데모**입니다. 새로고침하면 데이터가 초기화되고,
> 브라우저마다 데이터가 따로 갑니다(각자 메모리에서 도니까요).

### ⚠️ SPA 폴백 설정 — 없으면 새로고침이 404

이 앱은 주소를 브라우저가 처리합니다. 서버는 `/login` 이라는 파일을 갖고 있지 않으므로,
그 주소를 직접 열거나 새로고침하면 **404** 가 납니다. 호스팅마다 폴백을 설정해야 합니다.

| 호스팅 | 설정 | 상태 |
|---|---|---|
| Netlify / Cloudflare Pages | `public/_redirects` | ✅ 포함됨 |
| Vercel | `vercel.json` | ✅ 포함됨 |
| GitHub Pages | `npm run build:pages` (404.html 생성) | ✅ 스크립트 있음 |
| nginx / S3+CloudFront | 아래 참고 | ⚠️ 직접 설정 |

**nginx**

```nginx
server {
  root /var/www/tikat;

  # 정적 파일이 있으면 그대로, 없으면 index.html (SPA 라우팅)
  location / {
    try_files $uri $uri/ /index.html;
  }

  # 서비스워커·매니페스트는 캐시하지 않습니다.
  # 캐시되면 새 배포가 사용자에게 며칠씩 안 갑니다.
  location = /sw.js {
    add_header Cache-Control "no-cache";
  }
  location = /manifest.webmanifest {
    add_header Cache-Control "no-cache";
  }

  # 해시가 붙은 에셋은 오래 캐시해도 안전합니다.
  location /assets/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
  }
}
```

**S3 + CloudFront** — CloudFront 오류 페이지에서 403·404 를 `/index.html` (200) 로 응답하도록 설정합니다.

### HTTPS 가 필요한 기능

| 기능 | 이유 |
|---|---|
| 얼굴 등록 (카메라) | `getUserMedia` 는 HTTPS 또는 localhost 에서만 동작 |
| PWA 설치 | 서비스워커가 HTTPS 필요 |
| 결제창 | 대부분의 PG 가 HTTPS 를 요구 |

`http://` 로 배포하면 이 세 가지가 조용히 실패합니다.

## 12. 결제 (토스페이먼츠)

프론트가 하는 일은 **결제창 호출과 인증까지**입니다. 승인은 백엔드가 합니다.

```
① prepare   POST /payments/prepare        서버가 주문 생성 + 금액·orderId 확정
        ↓
② 결제위젯   widgets.requestPayment()      사용자 인증 (카드·간편결제)
        ↓  성공하면 successUrl 로 페이지 이동
③ confirm   POST /payments/confirm        백엔드가 토스 승인 API 호출 → 티켓 발급
```

### 결제위젯은 시트에 담습니다

`renderPaymentMethods()` 가 만드는 UI 는 500px 가까이 됩니다.
결제 페이지 본문에 그대로 붙이면 금액·약관·버튼이 저 아래로 밀리고,
스크롤 도중 위젯 iframe 위를 지나가 누르기도 어려워집니다.

**결제할 때만 시트로 덮습니다** (`TossPaymentSheet`) — 새 창처럼 동작하고
본문 레이아웃은 짧게 유지됩니다. 시트 본문은 스크롤되고 결제 버튼은 하단에 고정입니다.
결제가 진행되는 동안에는 닫히지 않습니다(`dismissible={false}`) —
중간에 닫으면 사용자는 취소된 줄 알지만 실제로는 창이 떠 있을 수 있습니다.

개별 연동 키(`test_ck_...`)를 쓰면 토스가 **진짜 새 창**을 띄우므로 시트는 뜨지 않습니다.

### 결제위젯은 팝업이 아니라 페이지 안에 들어옵니다

`renderPaymentMethods()` / `renderAgreement()` 가 지정한 자리에 토스의 UI 를 삽입합니다.
그래서 **결제 버튼을 누르기 전에 미리 그려둬야** 합니다. (`useTossWidget`)
버튼을 누르는 순간 만들 수 없습니다.

### ⚠️ 토스는 성공 시 "항상" 리디렉션입니다

`successUrl` 을 주면 인증 성공 후 그 주소로 **페이지가 이동**합니다.
데스크톱·모바일 구분 없이 성공 결과는 리디렉션으로만 돌아옵니다.

```
successUrl?paymentKey=...&orderId=...&amount=...
failUrl?code=...&message=...&orderId=...
```

그래서 결제 결과 라우트(`BOOKING_PAYMENT_RESULT`)가 **필수**입니다.
그 라우트는 **로그인 가드만** 통과하면 되도록 두세요. 얼굴 등록·OTP 가드를 걸면
결제는 끝났는데 승인 요청을 못 보내 **"돈은 빠졌는데 티켓이 없는"** 사고가 납니다.

예매 플로우 스토어(`bookingStore`)를 sessionStorage 에 유지하는 것도 이 때문입니다.
메모리에만 두면 리디렉션 복귀 때 선점·멱등키가 사라집니다.

### 금액은 서버가 정하고, 서버가 다시 검증합니다

프론트가 계산한 금액을 결제창에 넣고 그대로 믿으면 **1원 결제**를 만들 수 있습니다.
화면은 금액을 *보여주기만* 하고, 결제창에 넣는 값은 `prepare` 응답을 그대로 전달합니다.

승인 단계에서 프론트가 보내는 `amount` 는 **주소창(successUrl 쿼리)에서 온 값**이라
사용자가 고칠 수 있습니다. 백엔드는 이 값을 믿지 말고 `prepare` 때 저장한 금액과
비교한 뒤, **저장된 금액으로** 승인해야 합니다.

```
POST https://api.tosspayments.com/v1/payments/confirm
Authorization: Basic base64(SECRET_KEY + ':')
{ paymentKey, orderId, amount }   ← amount 는 서버가 저장한 값
```

시크릿 키(`test_sk_...`)는 **절대 프론트에 두지 않습니다.**

### 토스 규격 — 어기면 결제창이 안 열립니다

| 항목 | 규격 |
|---|---|
| `orderId` | **6~64자, 영문·숫자·`-`·`_` 만.** 한글·공백 불가 |
| `orderName` | 100자 이내 |
| `customerMobilePhone` | 숫자만 (하이픈 불가) |
| `amount` | 정수 (원 단위) |

서버가 `orderId` 를 만들 때 이 규칙을 지켜야 합니다. (목업은 `tikat-{timestamp}-{rand}`)

### 결제수단 — 지금은 둘뿐입니다

| 화면 표시 | 실제 동작 |
|---|---|
| 간편결제 (토스) | 토스 통합결제창 — 카드·토스페이·네이버페이가 한 창에 (`method: 'CARD'` + `flowMode: 'DEFAULT'`) |
| 포도알로 결제 | **PG 를 타지 않습니다.** 서버가 잔액을 차감하고 바로 티켓 발급 |

카드·계좌이체·가상계좌는 화면에서 뺐습니다.
(가상계좌는 입금 웹훅이 있어야 완료라서 시연에 맞지 않습니다)

**포도알 결제에는 결제창도 리디렉션도 없습니다.** `prepare → confirm` 두 번이면 끝입니다.
화면에 보이는 포도알 개수는 어림값이고, **차감량은 서버가 다시 계산**합니다.
프론트가 계산한 숫자를 그대로 차감하면 공짜 티켓이 나옵니다.

### 실제 테스트 결제 켜기 — 이미 켜져 있습니다

토스가 **가입 없이 쓰라고 공개한 문서용 테스트 키**가 `.env` 에 들어 있습니다.
그대로 실행하면 진짜 토스 결제 UI 가 뜨고, 결제하기를 누르면 `toss.im` 으로 넘어갑니다.

```bash
VITE_TOSS_CLIENT_KEY=test_gck_docs_Ovk5rk1EwkEbP0W43n07xlzm
```

### ⚠️ 클라이언트 키는 두 종류이고, 서로 호환되지 않습니다

| 키 | 짝이 되는 SDK | 화면 |
|---|---|---|
| `test_ck_...` (API 개별 연동 키) | `tossPayments.payment()` | 팝업 결제창 |
| `test_gck_...` (**결제위젯** 연동 키) | `tossPayments.widgets()` | 페이지에 삽입 |

잘못 짝지으면 결제가 아예 시작되지 않고 이 메시지가 뜹니다.

```
API 개별 연동 키의 클라이언트 키로 SDK를 연동해주세요. 결제위젯 연동 키는 지원하지 않습니다.
```

공개된 문서용 키가 **위젯 키뿐**이라 이 프로젝트는 위젯을 씁니다.
개별 연동 키(`test_ck_...`)를 발급받아 팝업 결제창으로 바꾸려면
`paymentGateway.ts` 의 `mountWidget` / `requestPayment` 만 고치면 됩니다.

### 🔴 시크릿 키는 절대 프론트에 두지 않습니다

문서에는 시크릿 키(`test_gsk_...`)도 같이 적혀 있지만, **승인 API 전용**이고
**백엔드 환경변수**에만 둡니다. `VITE_` 로 시작하는 값은 빌드 시 번들에 그대로 박혀
브라우저 개발자도구에서 누구나 읽을 수 있습니다. 프론트에 두면
아무나 그 상점의 결제를 승인·취소할 수 있습니다.

| 모드 (`VITE_PAYMENT_MODE`) | 동작 |
|---|---|
| `auto` (기본) | 키가 있으면 실제 위젯, 없으면 모의 결제 |
| `toss` | 항상 실제 위젯 (키 없으면 안내 메시지) |
| `mock` | 항상 모의 결제 (확인 창) |

> ⚠️ 결제 인증은 **HTTPS 에서만** 정상 동작합니다. (localhost 는 예외)

### 폴더 구조 — PG 의존은 한곳에

```
features/payment/
├── api/
│   ├── paymentGateway.ts   토스 SDK 호출 (auto/mock/toss) ← PG 교체 시 여기만
│   └── paymentApi.ts       우리 백엔드 (prepare / confirm)
├── model/
│   ├── payment.types.ts
│   └── payment.model.ts    취소인지 실패인지 판별
└── hooks/
    ├── usePayment.ts       ①②③ 오케스트레이션
    ├── useTossWidget.ts    위젯을 화면에 그리기
    └── usePaymentResult.ts 리디렉션 복귀 처리
```

화면은 `usePayment` 만 압니다. SDK 는 동적 import 라서 모의 결제 모드에서는 로드되지 않습니다.

### 취소는 에러가 아닙니다

사용자가 결제창을 닫은 것을 실패로 처리하면 "결제 실패했습니다" 토스트가 떠서
문제가 생긴 줄 알고 불안해합니다. `payment.model.ts` 의 `toPaymentFailure` 가
토스의 취소 코드(`PAY_PROCESS_CANCELED` 등)를 판별하니, 취소면 **조용히 되돌아갑니다.**

### 진행 단계를 보여주세요

결제창이 열린 동안 사용자는 뭘 기다리는지 모릅니다.
`usePayment` 의 `stage` 를 버튼 문구로 씁니다.

| stage | 버튼 문구 |
|---|---|
| `preparing` | 주문 확인 중 |
| `authenticating` | 결제창에서 진행해 주세요 |
| `confirming` | 결제 승인 중 |
