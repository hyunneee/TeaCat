## 0. 이 앱이 지향하는 인상

**"차분한 종이 위에 짙은 초록 한 점."**

티켓팅은 사람이 긴장한 채로 쓰는 앱입니다. 화면이 시끄러우면 실수합니다.
바탕은 눈이 편한 오프화이트로 비워 두고, **지금 눌러야 할 것 하나만** 초록으로 세웁니다.

| | |
|---|---|
| 비율 | **70 바탕 : 25 구조 : 5 강조** (1장) |
| 강조색 | `#3D5335` 짙은 초록 — 누를 것 · 선택된 것 · 진행 중인 것 |
| 바탕 | 순백이 아닌 오프화이트. 큰 면적의 `#fff` 는 눈이 부십니다 |
| 글자 | 순검정이 아닌 짙은 중성. `#000` 은 대비가 세서 오래 못 읽습니다 |
| 위계 | 색이 아니라 **명도·굵기·여백**으로 |
| 모션 | 절제해서. 단, **좌석·결제 화면은 더 빠르게** |
| 발광(glow) | 쓰지 않습니다. 그림자와 테두리로만 층을 만듭니다 |
| 예외 | 되돌릴 수 없는 동작(붉은색) · 좌석 상태 · 포토카드 등급 |

### 판단 기준 4가지

새 화면을 만들 때 이걸로 자문하세요.

1. **구분되는가** — 스크롤할 때 어디서 어디까지가 한 덩어리인지 보이는가?
2. **다음 행동이 보이는가** — 초록 버튼이 화면에 **하나만** 있는가?
3. **초록이 5% 를 넘지 않는가** — 넘으면 강조가 강조가 아닙니다
4. **되돌릴 수 없는 건 붉은가** — 로그아웃·탈퇴·취소가 일반 버튼과 같아 보이지 않는가?

## 1. 색 — 70 : 25 : 5

이 앱의 색은 **세 덩어리**뿐입니다. 비율은 자로 재는 게 아니라 눈에 보이는 면적입니다.

| 비율 | 역할 | 무엇 | 토큰 |
|---|---|---|---|
| **70** | 바탕 | 오프화이트 — 화면의 대부분 | `--color-canvas`, `--color-surface-1~3` |
| **25** | 구조 | 글자·경계·헤더·홈 히어로의 어두운 면 | `--color-ink-*`, `--color-brand-*` |
| **5** | 강조 | **짙은 초록 `#3D5335`** | `--color-accent-*` |

```
┌───────────────────────────────┐
│ ███████ 25 구조 ███████        │  헤더 · 홈 히어로 · 제목
│                               │
│  ░░░░░░░ 70 바탕 ░░░░░░░░      │  카드 · 목록 · 여백
│  ░░░░░░░░░░░░░░░░░░░░░░░      │
│  ░░░░░░░░░░░░░░░░░░░░░░░      │
│         ▓▓ 5 강조 ▓▓          │  지금 눌러야 할 버튼 하나
└───────────────────────────────┘
```

### 5% — 초록은 아껴 쓸수록 강해집니다

`#3D5335` = `--color-accent-700`. **초록을 쓰는 자리는 셋뿐입니다.**

| 언제 | 예 | 어떻게 |
|---|---|---|
| **지금 어디에 있나** | 하단 탭의 활성 탭 | `text-accent-700` |
| **지금 진행 중인 것** | 예매 진행 바(`Stepper`), 좌석 선점 타이머 | `bg-accent-700` |
| **캣머니가 오가는 확정** | 포카 구매·판매 등록 | `Button variant="primary"` |

이 **셋**이 전부입니다. 나머지는 무채색입니다.

> 딱 하나의 예외 — 로그인 화면의 **SAFE`TYCAT`CH**. 한 단어 안에 서비스 이름이
> 들어 있어 그 다섯 글자만 강조색으로 칠합니다. **로고 취급**이라
> "글자를 초록으로 쓰지 말 것" 규칙 밖입니다. 다른 화면에 복제하지 마세요.

> **큰 짙은 면은 강조색(#3D5335)입니다.** 홈 상단, 마이페이지 상단,
> 세그먼트(구매/판매 · 관람예정/지난)의 선택 알약 — 넷 다 `.surface-strong` 입니다.
> 앱의 인상을 만드는 면이라 브랜드 색으로 칠하고, 그 위의 글자·아이콘은 흰색입니다.
>
> 🔴 **색은 `--color-strong` 한 곳에만 적습니다** (styles/index.css 의 `:root`).
> 화면 코드에 `bg-accent-700` 을 적는 순간 "한 곳에서 바꾸기" 가 깨지고,
> 다음에 색을 바꿀 때 또 네 군데를 찾아다녀야 합니다.

### 붉은색의 두 번째 자리 — "지금 열려 있음"

붉은색은 원칙적으로 **되돌릴 수 없는 동작** 전용입니다. 예외가 하나 있습니다.

| | 색 | 뜻 |
|---|---|---|
| `Button variant="danger"` · `ListRow danger` | 붉은 글자/면 | 조심하세요 (취소·삭제·탈퇴) |
| `Badge tone="live"` · `<LiveDot />` | 옅은 붉은 면 + 붉은 글자 | **지금 진행 중** (예매중 · 경매 진행 중) |

방송의 LIVE 표시와 같은 관습이라 "지금 열려 있다"로 읽히지, 경고로 읽히지 않습니다.
**대신 버튼에는 절대 쓰지 마세요** — 상태 칩 전용입니다. 버튼에서 두 뜻이 겹치면
"취소"와 "예매중"이 같은 색이 되어 규칙이 무너집니다.

### 예매 플로우(1~5단계) — 진행 표시만 초록, **버튼은 검정**

봇 확인 → 구역 → 좌석 → 확인 → 결제에서 초록이 나오는 자리는
**진행 바와 선점 타이머** 둘뿐입니다. 둘 다 "지금 진행 중"을 뜻합니다.

버튼과 선택 표시를 초록으로 두지 않는 이유는 두 가지입니다.

1. 단계마다 초록 버튼이 하나씩 나오면 초록이 "다음"의 색이 되어 특별함을 잃습니다.
2. 좌석맵의 좌석 색(초록 = 고를 수 있음)과 경쟁합니다.
   이 화면에서 초록이 뜻해야 하는 건 **자리**이지 버튼이 아닙니다.

| 자리 | 어떻게 |
|---|---|
| 진행 바(`Stepper`) · 선점 타이머(`HoldTimer`) | **`bg-accent-700`** |
| 각 단계의 다음 버튼 | `Button variant="dark"` (검정 채움) |
| 고른 구역·결제수단 | 테두리 `border-2 border-brand-900` (두께는 항상 2px — 고를 때 칸이 흔들리지 않게) |
| 입력 포커스 | `focus-within:border-brand-900` |
| 로딩 스피너 | `text-brand-900` |
| **좌석 색** | 그대로 둡니다 — `--color-seat-*` (색 예외, 1장 참고) |

좌석 범례의 초록 사각형은 버튼과 무관한 **상태 색**입니다.
가용성은 색이 가장 빠른 신호이고, 지우면 범례가 성립하지 않습니다.

특히 아래는 **초록으로 칠하지 마세요.**

- ❌ 바로가기·메뉴 **아이콘** (화면마다 반복되면 그건 장식입니다)
- ❌ 섹션 제목의 막대, 안내 카드의 아이콘 배경
- ❌ "예매중" 같은 **상태 뱃지** — 목록에 여러 개면 초록이 그만큼 반복됩니다
      (예매중은 붉은 칩 `Badge tone="live"` 입니다. 아래 "LIVE 붉은색" 참고)
- ❌ 필터·세그먼트의 선택 표시 (필터는 "지금 눌러야 할 것" 이 아닙니다)
- ❌ 링크 글자 (밑줄이면 링크인 게 충분히 보입니다)
- ❌ **거래가 아닌 주 행동 버튼** — 로그인·가입·얼굴 등록·티켓 보기

거래가 아닌 주 행동에는 `variant="dark"`(검정 채움)를 쓰세요.
눈에 띄되 초록이 아니라, 결제 버튼의 초록이 특별해집니다.

| variant | 언제 |
|---|---|
| `primary` | 돈이나 좌석이 오가는 확정 버튼 |
| `dark` | 그 화면의 주 행동이지만 거래는 아닌 것 |
| `secondary` | 보조 행동 |
| `ghost` | 그보다 더 약한 것 |
| `danger` / `danger-ghost` | 되돌릴 수 없는 동작 |

그 밖에는 쓰지 마세요. 특히:

- ❌ 제목·본문 글자를 초록으로 (읽는 글은 `--color-ink`)
- ❌ 카드 배경을 초록으로 (강조가 배경이 되면 강조가 아닙니다)
- ❌ 한 화면에 `primary` 버튼 두 개 (둘 다 안 눌립니다 — 하나만 두고 나머지는 `secondary`)
  - 예외: **목록의 반복 항목**(회차별 "예매", 구역별 "신청")은 각 행의 주 동작이라 괜찮습니다.
    단 그 위에 덮개나 별도 CTA 가 뜨면 행 버튼을 `secondary` 로 내리세요.
- ❌ 아이콘을 전부 초록으로 (아이콘은 글자색을 따릅니다)

> 채도를 올리지 마세요. `#3D5335` 는 채도가 낮은(chroma ≈ 0.055) 색입니다.
> 쨍한 초록으로 바꾸면 이 앱의 인상이 통째로 달라지고 흰 글자 대비도 나빠집니다.

### 70% — 순백을 쓰지 않습니다

큰 면적의 순백(`#fff`)은 밝은 곳에서 눈이 부시고 어두운 곳에서 번져 보입니다.
**채도 0 의** 오프화이트를 씁니다. 중성색에 색기를 섞으면 화면 전체가 은은하게
물들어 보이고, 정작 강조색이 눈에 덜 띕니다.

```css
--color-canvas:    oklch(0.985 0 0);  /* 페이지 바탕 */
--color-surface-1: oklch(1 0 0);      /* 카드 — 캔버스보다 밝아야 떠 보입니다 */
--color-surface-2: oklch(0.962 0 0);  /* 입력창·눌린 면 */
--color-surface-3: oklch(0.925 0 0);  /* 한 단계 더 눌린 면 */
```

### 25% — 순검정도 쓰지 않습니다

`#000` 은 대비가 너무 세서 오래 읽으면 눈이 아픕니다. 글자도 **채도 0** 입니다.

```css
--color-ink:        oklch(0.24 0 0);  /* 본문 */
--color-ink-muted:  oklch(0.47 0 0);  /* 보조 설명 */
--color-ink-subtle: oklch(0.53 0 0);  /* 라벨·힌트 — AA 하한. 더 밝히지 마세요 */
```

큰 짙은 면(`.surface-strong`)은 `--color-strong` 입니다 — 지금은 강조색과 같은
#3D5335 이고, 흰 글자 대비 8.4:1 로 충분히 읽힙니다.
순검정에 가까운 값은 흰 본문과의 경계에서 대비가 너무 세서 쓰지 않습니다.

이 변수는 **홈 상단 · 마이 상단 · 세그먼트 알약 넷이 함께 보는 단일 출처**입니다.
색을 바꾸려면 이 한 줄만 고치세요.

위계는 **색이 아니라 명도·굵기·여백**으로 만듭니다.
"안 보여서" 색을 넣고 싶어지면, 먼저 글자 크기·굵기·여백을 손보세요.

### 이 셋 밖의 예외 — 셋뿐입니다

| 예외 | 토큰 | 왜 |
|---|---|---|
| 되돌릴 수 없는 동작 | `--color-danger` | 초록은 "누르세요", 붉은색은 "조심하세요" |
| 지금 열려 있음 | `LiveDot` (붉은 점) | 방송의 LIVE 표시와 같은 관습 — 위험이 아니라 **살아 있음** |
| 좌석 상태 | `--color-seat-*` | 가용성은 색이 가장 빠른 신호 |

```css
/* 좌석 — 이 다섯 줄만 고치면 좌석맵·범례·선택바가 함께 바뀝니다 */
--color-seat-available: oklch(0.66 0.12 145);   /* 초록 — 고를 수 있음 */
--color-seat-selected:  oklch(0.415 0.055 138); /* 강조색 — 내가 고른 자리 */
--color-seat-held:      oklch(0.78 0.13 80);    /* 노랑 — 다른 사람이 결제 중 */
--color-seat-sold:      oklch(0.84 0.004 140);  /* 회색 — 판매 완료 */
--color-seat-blocked:   oklch(0.91 0.004 140);

```

**화면 코드에 색을 직접 적지 마세요.** 좌석은 `SEAT_FILL` 테이블을 거쳐서만 씁니다.
그래야 색을 바꿀 때 한 곳만 고치면 됩니다.

### 색을 늘리고 싶을 때

늘리지 마세요. 정말 필요하면 CLAUDE.md 0번 절차입니다.
그 전에 이걸 먼저 시도하세요 — 대개 이걸로 풀립니다.

1. 글자 **굵기**를 올린다 (`font-medium` → `font-bold`)
2. **여백**을 준다 (붙어 있어서 안 보이는 경우가 대부분)
3. **면**을 나눈다 (`Card` 로 감싸거나 구분선을 넣는다)
4. 그래도 안 되면 **강조색**을 아주 좁게 쓴다

## 2. 그림자와 발광

검은 배경 위의 검은 그림자는 보이지 않습니다. 대신 **위쪽 테두리 하이라이트**로 면을 분리합니다.

| 유틸리티 | 용도 |
|---|---|
| `edge-light` | **카드 기본값.** 위쪽 테두리에 얕은 빛 + 아래 그림자 |
| `shadow-card` | 한 겹(6%). 이미 구분이 되는 면 — 버튼, 배지, 안쪽 카드 |
| `shadow-list` | **목록 항목**(공연·티켓). 붙는 그림자 + 퍼지는 그림자 두 겹 |
| `shadow-pop` | 모달 |
| `shadow-glow` / `shadow-glow-sm` | 브랜드 발광 |
| `shadow-glow-danger` | 위험 강조 |

### 🚫 발광은 기본적으로 쓰지 않습니다

버튼 hover, 카드 hover, 입력 포커스, 탭 인디케이터, 단계 표시 — 전부 **발광 없이**
테두리 색과 배경 단계로만 반응합니다.

발광이 허용되는 곳은 지금 둘뿐입니다.

1. **선택된 좌석** — 수백 개 중 내가 고른 것을 찾아야 하므로 (SVG 필터, 약하게)
2. **1분 남은 선점 타이머** — 놓치면 좌석을 잃으므로

> 화면 여기저기가 빛나면 "무엇이 중요한지"를 알 수 없게 됩니다.
> 새 발광을 추가하고 싶다면 위 둘만큼 급한 일인지 먼저 따져보세요.

> 이 유틸리티들은 `@theme` 의 `--shadow-*` 가 아니라 **`@utility`** 로 정의돼 있습니다.
> `--shadow-*` 네임스페이스는 색 치환 로직 때문에 유틸리티가 생성되지 않는 경우가 있어서
> `hover:shadow-glow` 같은 변형까지 확실히 도는 `@utility` 를 씁니다.

---

### 예외 — 포토카드의 빛 반사

포토카드 **상세 화면 한 장**만 표면에 사선(`/`)으로 빛이 스칩니다.
실물 카드를 기울일 때 반사되는 그 느낌이고, 이 서비스에서 카드가 "물건"이라는
유일한 촉감입니다. (`features/nft/components/PocaShowcase.tsx`)

지켜야 할 선:

- **목록에는 절대 넣지 않습니다.** 12장이 전부 반짝이면 아무것도 특별하지 않습니다
- **무한 루프 금지.** 들어왔을 때 한 번, 그리고 **누를 때마다** 한 번 훑고 멈춥니다
- 카드를 3D 로 기울이지 않습니다 — 빛만 지나갑니다
- 발광(glow)이 아니라 **반사**입니다 — 흰색 반투명 띠, 주변으로 빛이 번지지 않습니다
- `prefers-reduced-motion` 이면 정지 상태로 둡니다

### 밝은 바탕에서는 선과 그림자가 경계를 만듭니다

바탕을 밝게 유지하면 카드와 바탕의 **밝기 차이만으로는** 경계가 안 보입니다
(현재 대비 1.07). 그래서 구분은 다음 둘이 담당합니다.

- `--color-line` — 카드 테두리. 너무 밝히면 카드가 배경에 녹습니다
- `edge-light` — **두 겹** 그림자(붙는 그림자 + 퍼지는 그림자). 한 겹은 종이처럼 안 보입니다

바탕을 더 어둡게 해서 대비로 푸는 방법도 있지만, 큰 면적이 어두워지면
화면이 무거워 보입니다. 밝은 바탕 + 또렷한 선 쪽을 씁니다.

### ⚠️ `ring-*` 과 `edge-light` 는 같이 못 씁니다

둘 다 `box-shadow` 를 씁니다. 카드에 `edge-light`(그림자)가 붙어 있으면
`ring-2` 는 **조용히 사라집니다** — 클래스는 있는데 화면에는 안 보이는 상태라 찾기 어렵습니다.

강조가 필요하면 **테두리 두께**로 하세요.

```
❌ 'edge-light border-accent-400 ring-2 ring-accent-200'
✅ 'edge-light border-2 border-accent-500'
```

## 3. 모션

### 강도 기준

| 화면 | 정책 |
|---|---|
| 일반 화면 | 진입 애니메이션 + 리스트 순차 등장 + 상태 전환 |
| **좌석 선택 · 결제** | **지연을 만드는 애니메이션 금지.** 속도가 곧 UX |
| 완료 · 당첨 | 체크 표시가 스프링으로 나타나는 정도. **축포·파티클은 쓰지 않습니다** |

**무한 반복 애니메이션은 기본적으로 금지입니다.** 계속 움직이는 것이 화면에 있으면
시선을 계속 뺏기고, 정작 상태가 바뀌었을 때 눈치채지 못합니다.
예외는 `LiveDot`(실시간 폴링 중), `Skeleton`(로딩 중), 1분 남은 타이머뿐입니다.
모두 "지금 무언가 진행 중"이라는 정보를 담고 있습니다.

### 지속시간 — [`shared/lib/motion.ts`](src/shared/lib/motion.ts) 에서만 가져옵니다

```ts
DURATION.quick  0.14s   즉각 반응 (호버, 퇴장)
DURATION.base   0.24s   기본 (진입, 전환)
DURATION.slow   0.36s   강조 (완료 화면)
SPRING                  위치·크기 이동 (탭 인디케이터, 선택 표시)
```

화면마다 duration 을 새로 적으면 "이 화면만 느리다"는 인상이 생깁니다.

### 준비된 패턴

| 도구 | 용도 |
|---|---|
| `<PageTransition />` | 라우트 전환 시 스크롤 정리 (**연출은 없습니다** — 아래 참고) |
| `<Stagger>` / `<Stagger.Item>` | 목록 순차 등장 |
| `<AnimatedNumber>` | 금액·잔액이 굴러 올라감 |
| `<LiveDot />` | 실시간 갱신 중 (좌석·구역) |
| `animate={{ x: `${i * 100}%` }}` | 세그먼트 선택 알약이 미끄러져 이동 |

⚠️ **`layoutId`(공유 레이아웃)를 선택 표시에 쓰지 마세요.** layout 애니메이션은
뷰포트 기준으로 위치를 재서 차이를 되돌리는 방식이라, `sticky` 영역 안에서
그 사이 스크롤이 움직이면 잰 값이 어긋나 **알약이 화면 밖에서 날아 들어옵니다.**
칸 폭이 같으면 위치는 `인덱스 × 100%` 로 정확히 계산됩니다 — 재지 마세요. (`Segmented`)

### 동작 줄이기 — 끄는 것은 "연출" 이지 "조작" 이 아닙니다

`prefers-reduced-motion: reduce` 면 **저절로 움직이는 것**을 끕니다 —
등장·퇴장, 빛 반사, 스프링 반동, 자동 스크롤.

**손가락을 따라가는 직접 조작은 끄지 마세요.** 끌어서 기울이기·스와이프는
애니메이션이 아니라 조작 그 자체라, 막으면 그 기능이 통째로 사라집니다.

🔴 이게 실제로 사고가 났던 자리입니다 — 포토카드 확대의 기울이기가
`if (reduced) return` 으로 막혀 있었는데, **안드로이드는 절전 모드만 켜도**
이 값이 reduce 가 되어 "실제 휴대폰에서만 안 되는" 증상이 됐습니다.
PC 는 대개 꺼져 있어 재현되지 않습니다. (`PocaFullscreen`)

### 확대해서 보는 화면은 `Lightbox` 하나

포토카드 확대, 공연 포스터 확대 — 검은 배경·닫기 버튼·ESC·배경 스크롤 잠금은
`shared/components/ui/Lightbox` 가 전부 합니다. 안에 무엇을 넣을지만 정하세요.
**비슷한 전체화면 뷰어를 새로 만들지 마세요.**

- 포토카드: 기울이기 + 빛 반사 (소유한 카드에서만)
- 포스터: 그림만. 기울이기·반짝임은 "내 것" 의 연출이라 여기 붙이지 않습니다

### 손가락으로 만지는 것에는 `touch-none` 과 `no-select`

끌기를 받는 요소에는 셋이 함께 필요합니다. 하나라도 빠지면 **PC 에서는 되고
실제 휴대폰에서만** 끊깁니다.

| | 왜 |
|---|---|
| `touch-none` | 손가락 움직임을 브라우저가 스크롤로 가져가지 않게 |
| `no-select` | 길게 누를 때 뜨는 선택·이미지 저장 메뉴 차단 (뜨는 순간 `pointercancel`) |
| `draggable={false}` (이미지) | 네이티브 이미지 드래그가 포인터를 뺏지 않게 |

이동은 `window` 에서 듣습니다. 요소에만 걸면 손가락이 조금만 벗어나도 끊기고,
`setPointerCapture` 는 브라우저에 따라 실패하거나 취소됩니다.

### ⚠️ 페이지 전환에 `AnimatePresence` 를 쓰지 마세요

`mode="wait"` 는 이전 화면의 exit 이 끝나야 새 화면을 붙입니다.
**한 번이라도 exit 이 끝나지 않으면 네비게이션이 그대로 멈춥니다.**
티켓팅 앱에서 화면이 안 넘어가는 건 치명적이라 나가는 연출을 쓰지 않습니다.
[`PageTransition`](src/shared/components/common/PageTransition.tsx) 은 이제
**아무 연출도 하지 않습니다** (아래 "화면 전환에 페이드도 쓰지 마세요").

### 접근성

`prefers-reduced-motion` 을 반드시 존중합니다.

- CSS 애니메이션 → `index.css` 의 미디어 쿼리가 자동 처리
- `motion/react` → `useReducedMotion()` + `reduceIfNeeded()` 사용
- 🔴 **기능을 없애지 마세요.** 안드로이드는 **절전 모드만 켜도** reduce 라,
  존중한다고 지워버리면 "실제 폰에서만 없는 기능" 이 됩니다.

| 연출 | reduce 일 때 |
|---|---|
| 화면·목록 등장 등 **자리를 옮기는** 연출 | **끕니다** (원래 목적) |
| 끌어서 기울이기 (직접 조작) | 그대로 — 연출이 아니라 조작입니다 |
| 포토카드 빛 반사 (`useGlareSweep`) | 그대로 — 레이아웃을 밀지 않는 반투명 띠 하나 |

정지 상태로 대체하는 방법도 써 봤지만 "멈춰 있는 오류" 로 읽혔습니다.
줄여야 한다면 없애지 말고 **반복을 빼세요**(`repeatMs` 생략 → 한 번만).

---

### 화면 전환에 페이드도 쓰지 마세요

새 화면을 `opacity: 0 → 1` 로 띄우면 그 0.24초 동안 보이는 건 **앱의 흰 바탕**입니다.
홈·마이페이지처럼 위쪽이 짙은 화면으로 넘어갈 때 이게 **흰 화면이 한 번 깜빡이는 것**으로
보입니다 (휴대폰에서 특히 눈에 띕니다). 그래서 페이드를 걷어냈고, 전환은 즉시입니다.

등장 연출이 필요하면 화면 전체가 아니라 **안의 요소**에 넣으세요 (`Stagger`).
화면 전체를 투명하게 만드는 연출은 그 뒤의 배경색을 그대로 노출시킵니다.

같은 이유로 **로딩 표시는 늦게** 나타납니다(`PageLoader delayMs` 기본 180ms).
캐시된 코드 조각은 수십 ms 만에 오는데, 그 사이 점 3개가 켜졌다 꺼지면
그것도 깜빡임으로 읽힙니다. 그리고 자주 가는 화면은 `warmRoutes()` 가
첫 페인트 뒤 유휴 시간에 미리 받아 둡니다 — 이동할 때 빈 화면이 안 보입니다.

### 페이지 전환에 transform 을 쓰지 마세요

`transform` 이 걸린 요소는 자손 `position: fixed` 의 **기준(containing block)** 이 됩니다.
페이지 래퍼에 `y: 10 → 0` 같은 이동을 넣으면, 전환이 도는 0.24초 동안
하단 고정 버튼(`BottomBar`)이 뷰포트가 아니라 **문서 아래쪽**에 붙어 한 번 튑니다.
좌석·결제 화면에서 이건 그냥 버그로 보입니다.

그래서 `PageTransition` 은 **페이드만** 합니다. 같은 이유로 화면 전체를 감싸는
래퍼에 `scale`·`translate`·`filter` 를 넣지 마세요.

### 하단 네비게이션 — 탭마다 아이콘은 하나

활성 탭에 **색 면(알약)을 깔지 않습니다.** 탭마다 면이 깔리면 하단바가 무거워집니다.
색은 **글자와 아이콘에만** 씁니다.

🔴 **아이콘은 상태에 따라 바뀌지 않습니다.** 두 가지를 다 해 보고 되돌렸습니다.

| 시도 | 왜 안 되는가 |
|---|---|
| `fill='currentColor'` 로 채우기 | lucide 는 선 전용 세트라 채울 면이 없습니다. 겹친 선이 메워져 음표·티켓이 **덩어리로 뭉갭니다** |
| 활성일 때 더 촘촘한 글리프로 교체 | 같은 자리의 그림이 다른 그림으로 바뀝니다. 밀도가 오르는 게 아니라 **아이콘 세트를 섞어 쓴 것처럼** 이질적으로 보입니다 |

활성 표시는 **아이콘 밖에서** 합니다 — 아이콘 뒤에 강조색 **원**이 깔립니다.

| | 활성 | 비활성 |
|---|---|---|
| 아이콘 자리 | `size-10` (**정사각형 → 원**) | 같은 크기, 배경 없음 |
| 원 | `surface-strong` + `shadow-card`, 탭 사이를 **미끄러져 이동** | 없음 |
| 아이콘 | 같은 글리프, **흰색**, `strokeWidth 2.2` | 같은 글리프, `ink-subtle`, `strokeWidth 1.8` |
| 라벨 | `text-accent-800` · `font-bold` | `text-ink-subtle` · `font-medium` |

색·굵기만으로는 분간이 안 됩니다 — 짙은 초록과 회색은 둘 다 "어두운 글리프" 라
흘긋 보면 구별되지 않습니다. **면이 있고/없고**는 한눈에 보이고,
색을 못 보는 사람에게도 그대로 보입니다.

- 아이콘 자리는 **정사각형**이어야 원이 됩니다. 가로만 넓히면 알약이 되어
  하단바가 무거워 보입니다. 활성·비활성이 **같은 크기**여야 탭을 옮길 때 바가 안 들썩입니다.
- **원은 하나만 두고 자리를 옮깁니다.** 탭마다 원을 켜고 끄면 "뿅" 하고 순간이동합니다.
  위치는 `인덱스 × 100%`(칸 폭이 같으므로 정확), 이동은 `SPRING`.
  ⚠️ `layoutId` 는 쓰지 마세요 — 스크롤 뒤에 위치가 어긋납니다 (`Segmented` 와 같은 이유).
- 원의 **세로 위치를 px 로 맞추지 마세요.** 탭과 같은 세로 배치(같은 gap + 라벨 한 줄)를
  그대로 흉내내면 아이콘·라벨 크기를 바꿔도 저절로 따라옵니다.
- 활성 아이콘의 흰색은 `delay-150` 으로 **원이 도착한 뒤에** 적용합니다.
  바로 흰색이 되면 원이 오는 동안 흰 바탕에 흰 아이콘이라 잠깐 사라져 보입니다.
- 이 면은 화면에 **하나**뿐입니다(활성 탭 1개). "지금 선택된 것" 은 초록을 써도 되는
  세 자리 중 하나이고, 행동 버튼과 경쟁하지 않습니다. (1장)

강조색을 여기 써도 되는 이유: 하단바가 말하는 건 "지금 어디에 있나" 하나뿐이라
화면 안의 행동 버튼과 경쟁할 일이 없습니다. (흰 바탕 대비 8.44:1)

- 탭을 추가할 때는 `BottomNav` 의 `TABS` 테이블에 한 줄만 넣으세요 (아이콘 하나)
- 네비 높이 `--spacing-nav`(4.375rem), 아이콘 27px, 라벨 12.5px
- 배경은 반투명이 아니라 **불투명**입니다. 목록이 비쳐 보이면 지저분합니다.

### 폭죽은 한 흐름의 끝에서 한 번만

`<Confetti />` 는 예매 완료 화면 한 곳에서만 씁니다.
canvas 한 장에 그리고, 다 떨어지면 스스로 정리합니다. 회색 계단으로만 그립니다 —
폭죽만 알록달록하면 그 화면만 다른 앱처럼 보입니다.
`prefers-reduced-motion` 이면 아예 렌더하지 않습니다.

### 하단 고정 여백 — `pb-safe` 는 padding-bottom 을 덮어씁니다

`.pb-safe` 는 `padding-bottom: env(safe-area-inset-bottom)` 이라
`pb-8 pb-safe` 처럼 같이 쓰면 **pb-8 이 무시되고** 버튼이 화면 맨 아래에 붙습니다.
노치가 없는 안드로이드에서는 여백이 아예 0 이 됩니다.

여백이 필요한 곳은 한 번에 계산하세요.

```
pb-[calc(2rem+env(safe-area-inset-bottom))]
```

| `IconButton` | 아이콘 전용. `label` 필수 (스크린리더) |
| `Input` | 라벨·힌트·에러·아이콘 한 세트. 포커스 시 테두리 강조 |
| `Card` | `tone` = `default` `brand` `warning` `danger` `success` |
| `ListRow` | 설정/메뉴 한 줄. `danger` 지원 |
| `Badge` / `LiveDot` | 상태 라벨(`size` sm/md) / 실시간 표시 |
| `BannerCarousel` | 홈 상단 광고·이벤트 슬라이더 (`features/banner`) |
| `Segmented` | 탭. 인디케이터가 미끄러짐. 제네릭이라 값 타입이 좁혀짐 |
| `Stepper` | 예매 단계. 연결선이 채워짐 |
| `SectionTitle` | **구획 제목.** 앞에 브랜드 막대 |
| `AnimatedNumber` | 숫자 롤업 |
| `Modal` / `ConfirmModal` | 바텀시트·다이얼로그. `danger` 면 붉은 띠 + 경고 아이콘 |
| `PosterImage` / `PocaArt` | 이미지 없을 때 시드 기반 그라데이션 |
| `Skeleton` / `SkeletonList` | 로딩 자리 |

### 구획 나누기 — "구분이 안 된다"의 해법

카드만 쌓으면 스크롤할 때 전부 같은 덩어리로 보입니다.

```tsx
<section>
  <SectionTitle description="한 번 실행하면 되돌릴 수 없어요">위험 구역</SectionTitle>
  <Card tone="danger" padded={false} className="divide-danger/20 divide-y overflow-hidden">
    <ListRow danger ... />
  </Card>
</section>
```

- `<SectionTitle>` 로 구획을 열고
- 섹션 사이는 `space-y-6` 이상
- 목록은 `Card padded={false}` + `divide-y` 로 한 덩어리로 묶기

### 글꼴 — Pretendard

본문 글꼴은 **Pretendard** 입니다. (`index.html` 에서 CDN 으로 불러옵니다)
한글 자간과 숫자 폭이 UI 에 맞고, dynamic-subset 이라 화면에 쓰인 글자만 내려받습니다.

바꿀 때 화면 코드는 손대지 마세요. **두 곳만** 고칩니다.

1. `index.html` 의 `<link>` 교체
2. `--font-sans` 맨 앞의 이름 교체

```css
--font-sans: 'Pretendard Variable', Pretendard, var(--font-system);
```

`--font-system` 은 **폴백**입니다. 네트워크가 느리거나 CDN 이 막히면 여기로 떨어지므로
지우지 마세요. 글꼴을 아예 빼려면 `--font-sans` 를 `var(--font-system)` 으로만 두면 됩니다.

### 목록 항목에는 테두리를 두지 않습니다

공연 목록·내 티켓·대기 내역·거래 내역·포카 격자처럼 **같은 것이 여러 개** 놓이는
곳에서는 테두리를 쓰지 마세요. 선이 줄줄이 겹쳐 화면이 선으로 가득 찹니다.

`shadow-list` 를 쓰는 곳은 지금 다섯입니다 — 이 목록에 없는 화면에 목록이 생기면
같은 그림자를 쓰세요. **목록마다 그림자 세기가 다르면 화면을 옮길 때 층이 어긋나 보입니다.**
`ConcertCard` · `TicketCard` · `NftCard`(카드 뒤 회색 면) · `ResaleEntryCard` · 거래 내역 줄.

- 항목은 **흰 면 + 두 겹 그림자**(`surface shadow-list`)로 바탕에서 띄웁니다.
  바탕(canvas 0.985)과 카드(1.0)의 색 대비가 거의 없어서, **경계를 만드는 건 그림자뿐**입니다.
  한 겹짜리 `shadow-card` 로는 목록이 통째로 하나의 흰 면처럼 읽힙니다 —
  붙는 그림자(1px)가 경계를, 퍼지는 그림자(16px/-8px)가 높이를 만듭니다.
- 구분은 **여백**이 합니다 (항목 간 8px)
- 누를 수 있다는 건 **누름 반응**으로 알립니다 (`hover:bg-surface-2`)
- 강조가 필요하면 테두리가 아니라 **면**을 깝니다 (당첨 카드의 `bg-accent-50`)

테두리를 유지하는 곳은 **하나만 놓이는 안내 카드**입니다 —
홈의 "얼굴 등록을 완료해 주세요" 처럼 주변과 성격이 다른 한 장.

### 상태 뱃지는 제목 **위**, 첫 줄에

목록을 훑는 눈은 왼쪽 위에서 아래로 내려갑니다.
상태가 제목보다 먼저 와야 "이건 지금 살 수 있는 거구나" 를 판단하고 제목을 읽습니다.
포스터 위에 얹으면 아트를 가리고, 오른쪽 끝에 두면 제목을 다 읽은 뒤에야 보입니다.

### "지금 할 수 있는 것" 은 테두리로 세웁니다

목록에서 사용자가 찾는 건 **지금 살 수 있는 것 하나**입니다.
해당 카드만 `border-2 border-accent-400` 로 두르고, 나머지는 1px 회색으로 두어
저절로 뒤로 물러나게 합니다. 살아 있는 상태에는 `<LiveDot />` 를 붙입니다.

| 상태 | 표시 |
|---|---|
| 예매중 (공연 카드) | **카드 우상단 붉은 칩**(`tone="live"` + LiveDot) |
| 오픈 예정 (공연 카드) | 같은 자리의 회색 칩 (`tone="quiet"`) |
| 당첨 (대기 카드) | 제목 줄의 **진한 강조 칩** + 마감 카운트다운 |
| 대기 중 · 낙첨 | 제목 줄의 회색 칩 |

상태 칩은 카드 **모서리에 고정**하거나(공연 카드) **제목 줄 오른쪽**에 둡니다(대기 카드).
글의 흐름 안에 넣으면 제목 길이·줄 수에 따라 카드마다 자리가 달라져 스캔이 끊깁니다.
카드 위에 **머리띠(전체 폭 배너)를 두르지 마세요** — 무엇을 신청했는지보다
띠가 먼저 읽혀서 정작 공연 이름이 눈에 안 들어옵니다.

상태 뱃지를 **우상단에 박지 마세요.** 제목 자리를 뺏어 제목이 잘리고,
카드가 커질수록 제목과 멀어져 무엇의 상태인지 안 읽힙니다.
포스터가 있으면 포스터 위에 얹습니다.

### 빈 목록·로딩은 화면 가운데

`EmptyState` 와 `Loading` 은 `min-h-[48dvh]` 로 세로 가운데에 놓입니다.
목록 자리 맨 위에 붙어 있으면 "여기까지만 불러온 건가?" 로 읽혀서 스크롤을 계속하게 됩니다.
페이지의 **일부 구획**에 쓸 때만 `className="min-h-0"` 로 눌러주세요 (홈의 공연 목록 등).

### 버튼에도 테두리를 두지 않습니다

버튼이 둘 이상 나란히 놓이면 선이 겹쳐 지저분해집니다. 구분은 **면의 밝기**가 합니다.

| variant | 면 |
|---|---|
| `primary` | 강조색 채움 |
| `dark` | 검정 채움 |
| `secondary` | **흰 면 + 얕은 그림자** |
| `soft` | 연회색 면 |
| `ghost` | 면 없음 |

보조 버튼을 회색으로 어둡게 깔지 마세요 — "비활성" 처럼 읽힙니다.

### 입력창에도 테두리를 두지 않습니다

가입 폼처럼 입력칸이 여러 개 쌓이면 칸마다 선이 있는 화면은 **표처럼** 보이고,
정작 눌러야 할 버튼보다 입력칸이 더 세 보입니다. 구분은 **면**이 합니다.

| tone | 면 | 어디 |
|---|---|---|
| `default` | 연회색 | 폼 입력 (로그인·가입·비밀번호·판매 등록) |
| `contrast` | 흰 면 + 그림자 | 목록 위 검색 바 |

- 테두리 자체는 **투명하게 남겨둡니다.** 없애면 포커스·에러로 선이 생길 때
  칸 높이가 2px 씩 달라져 화면이 들썩입니다.
- 포커스는 `focus-within:border-brand-900` — 테두리가 없으니 **포커스 표시가
  유일한 초점 신호**입니다. 지우지 마세요(WCAG 2.4.7).
- 에러는 `border-danger` + 아래 붉은 문구.
- `contrast` 는 흰 입력창이 거의 흰 바탕에 놓입니다. `shadow-card`(6%)로는
  경계가 사라지므로 **10% 그림자**를 씁니다.

**글자 크기는 `Input`/`Textarea` 가 정합니다 (16px).**
화면에서 `className="text-[0.9375rem]"` 같은 걸 덧붙이지 마세요 —
검색창끼리 크기가 어긋나고, iOS 사파리는 **16px 미만** 입력칸에 포커스가 가면
화면을 확대해 버립니다(사용자가 직접 되돌려야 합니다).

**지우기(X) 버튼은 `onClear` 하나로 붙입니다.**
화면마다 `rightSlot` 에 X 를 직접 그리면 크기·간격·라벨이 조금씩 달라집니다.
`type="search"` 의 **브라우저 기본 X 는 CSS 에서 지워 두었습니다**
(`::-webkit-search-cancel-button`) — 안 지우면 X 가 두 개로 보입니다.

세 검색창(통합 검색·공연 목록·포카 마켓)은 **props 까지 같습니다** —
`tone="contrast"`, `type="search"`, `leftIcon={<Search size={17} />}`, `onClear`.
같은 기능이 화면마다 달라 보이면 사용자는 다른 기능으로 읽습니다.

### 상세 화면을 테두리로 잘게 나누지 마세요

한 장의 상품·티켓 정보인데 항목마다 테두리를 두르면 네다섯 덩어리로 갈라져
시선이 계속 끊깁니다. 구분은 **여백과 연회색 면**(`surface-2`)이 합니다.

세 줄 안팎의 정보 목록은 면도 깔지 말고 **여백만** 두세요 — 짧으면 저절로 묶여 보입니다.
본문 글자는 상세 화면에서 한 단계 크게(15px) 잡습니다. 12px 는 라벨용입니다.

카드가 여러 장 놓이는 화면(예매 플로우)에서는 `<Card flat>` 을 쓰세요 —
테두리 없이 **흰 면 + 얕은 그림자**만 남습니다. 테두리 두께는 투명하게 유지되므로
`flat` 을 켜고 꺼도 1px 씩 밀리지 않습니다.

### 상세 화면의 순서 — 읽고 나서 고릅니다

공연 상세는 **머리 → 소개 → 회차 선택 → 정책 안내** 순입니다.
"이게 무슨 공연인지" 를 판단하기 전에 날짜를 고르라고 하면 위아래로 오가며 다시 읽게 됩니다.

머리(포스터 + 제목)에서 제목·아티스트는 **위**, 장소·시간·연령은 **포스터 아래쪽에 맞춥니다**
(`flex flex-col justify-between`). 제목 바로 밑에 붙이면 셋이 한 덩어리로 뭉쳐
제목이 묻히고, 포스터 오른쪽에 빈 공간이 남아 화면이 성의 없어 보입니다.

### 안내 카드는 밝게

"얼굴을 등록해야 예매할 수 있어요" 같은 안내 카드에 회색 면을 깔면
비활성처럼 보여서 정작 읽어야 할 안내가 지나갑니다.
**흰 면 + 테두리 + 아이콘**으로 구분하세요. (안내 카드는 하나만 놓이므로 테두리를 유지합니다)

### 모달에는 장식선을 두지 않습니다

상단 띠·좌측 강조선처럼 **한쪽에만 있는 선**은 모달마다 달라 보이게 만듭니다.
위험한 동작이라는 신호는 선이 아니라 **내용과 버튼**으로 전합니다
(붉은 아이콘 + `Button variant="danger"`).

### 목록이 비어 있는 동안엔 도는 걸 보여주세요

스켈레톤만 깔면 "레이아웃이 깨진 건가?" 로 읽히는 경우가 있습니다.
목록(공연·티켓·포카)에는 `<Loading label="..." />` — 스피너와 문구를 함께 씁니다.
화면 전체가 비어 있을 땐 `<PageLoader />`, 이미지 자리처럼 크기가 정해진 곳만 `Skeleton`.

### 폼은 필수/선택을 먼저 보여줍니다

`<Input showRequirement required />` 이면 라벨 옆에 붉은 `*`, 아니면 "선택" 칩이 붙습니다.
검증 규칙은 화면이 아니라 **모델의 테이블**에 둡니다 (`SIGNUP_FIELDS`).
항목을 늘릴 때 화면을 고치지 않아도 되고, 규칙이 한 곳에 모입니다.

에러는 **한 번 건드린 항목부터** 보여주세요. 첫 글자에 빨간 글씨가 뜨면 혼나는 느낌이 듭니다.

## 5. 레이아웃

이 장이 **레이아웃의 기준**입니다. 화면을 새로 만들 때 여기부터 보세요.

### 화면 뼈대

모든 화면은 이 셋 중 하나입니다.

```
① 탭이 있는 화면 (AppLayout)        ② 전체화면 (PlainLayout)       ③ 하단 고정 버튼이 있는 화면
┌─────────────────┐               ┌─────────────────┐            ┌─────────────────┐
│ Header (sticky) │               │ Header          │            │ Header          │
├─────────────────┤               ├─────────────────┤            ├─────────────────┤
│                 │               │                 │            │                 │
│   본문 .pb-nav   │               │   본문          │            │   본문           │
│                 │               │                 │            │  <BottomBar.     │
├─────────────────┤               │                 │            │     Spacer />    │
│ BottomNav       │               └─────────────────┘            ├─────────────────┤
└─────────────────┘                                              │ BottomBar (고정) │
                                                                 └─────────────────┘
```

- ①은 홈·공연·포카·내 티켓·마이페이지. 본문 아래 여백은 레이아웃이 이미 넣습니다(`.pb-nav`).
- ②는 로그인·예매 플로우처럼 **한 가지 일에 집중해야 하는** 화면. 탭을 없애 이탈을 줄입니다.
- ③은 결제·좌석 선택처럼 **다음 행동이 하나로 정해진** 화면.
  `<BottomBar>` 를 쓰면 본문 끝에 `<BottomBar.Spacer />` 를 **반드시** 넣으세요. 없으면 마지막 항목이 가립니다.

### 폭과 여백

| | 값 | 왜 |
|---|---|---|
| 폭 | `.app-width` (폰은 화면 꽉 / 480px↑ 21rem = 336px) | 데스크톱에서도 **폰 화면 한 기둥** |
| 화면 좌우 여백 | `p-4` (16px) | 화면 가장자리에 글자가 붙지 않게 |
| 섹션 사이 | `space-y-6` | 이보다 좁으면 섹션이 하나로 뭉쳐 보입니다 |
| 카드 안쪽 | `p-4` · 촘촘한 목록은 `p-3.5` | |
| 목록 항목 사이 | `space-y-2` 또는 `divide-y` | 항목이 짧으면 구분선, 카드형이면 간격 |

여백은 **4의 배수**만 씁니다(`gap-1.5`=6px 처럼 이미 쓰는 반칸은 예외).
`gap-[13px]` 같은 값이 보이면 그건 눈대중으로 맞춘 것이고, 다음 사람이 또 눈대중으로 고칩니다.

### 데스크톱에서도 폰 화면 하나

이 앱의 모든 화면은 **한 손에 들어오는 폭**을 전제로 짜여 있습니다.
폭이 640px 로 늘어나면 포스터·배너·좌석맵이 같이 커져서, 디자인이 넓어지는 게 아니라
**모바일을 확대해 놓은 것처럼** 보입니다 (배너 하나가 456px 높이를 먹습니다).

| | 어떻게 |
|---|---|
| 폭 | `.app-width` — 폰은 캡 없음, **30rem(480px)부터** `--container-app`(21rem = 336px) |
| 바깥 바탕 | 30rem 이상에서 `surface-3` — 가운데 기둥이 '앱 화면'으로 읽힙니다 |
| 기둥 경계 | `.app-frame` 이 30rem 이상에서만 좌우 선을 그립니다 (폰에서는 없음) |

**폰에서는 상한을 걸지 않습니다.** 336px 을 무조건 씌우면 큰 폰(430px)에서
좌우에 빈 띠가 생겨 "화면에 안 맞는 앱" 이 됩니다. 캡은 화면이 앱 폭보다
확실히 넉넉해지는 480px 부터 걸리고, 그 위로는 창을 얼마나 넓히든 같은 폭입니다.

- **화면에 고정되는 것은 전부 `app-width`** 입니다 — 하단 탭·하단 버튼·업데이트 알림·
  모달·토스트. 하나라도 빠지면 데스크톱에서 그것만 화면 폭을 꽉 채워 기둥 밖으로 나옵니다.
  (모달 시트는 `justify-center` 도 함께 필요합니다 — 없으면 좁아진 시트가 왼쪽에 붙습니다)
- 모달 뒤 어두운 막은 **화면 전체**를 덮습니다. 기둥 안에만 깔면 바깥이 그대로 밝아
  모달이 눌린 것처럼 보입니다.
- 폭을 바꿀 때 고칠 곳은 `--container-app` 하나입니다 —
  `--banner-width` 는 같은 지점에서 이 값을 따라갑니다.

#### 예외 — 공연장 좌석 배치 관리자 작업 공간

`/admin/stadium`은 원본 좌석표 위에서 구역을 지정하고 많은 좌석을 보정하는 도구이므로
폰 폭으로 제한하지 않습니다. 이 경로만 `AdminWorkspaceLayout`의 `max-w-7xl` 폭을 사용합니다.

- 작은 화면에서는 화면 폭을 그대로 사용하고 편집 캔버스 영역만 가로 스크롤합니다.
- 일반 사용자 화면, 기존 관리자 모니터링, 모달·토스트의 `.app-width` 규칙은 유지합니다.
- 넓어진 공간에는 정보를 무작정 늘리지 않고 기본 정보·캔버스·편집 패널의 작업 열만 배치합니다.
- 이 예외를 다른 관리자 화면에 자동으로 확장하지 않습니다.

### 헤더 — 선 없이, 제목은 화면 가운데

- 아래 구분선(`border-b`)을 두지 않습니다. 스크롤하면 내용이 알아서 경계를 만듭니다.
- **반투명(글래스)로 두지 않습니다.** 뒤 내용이 비쳐 회색빛이 돌고,
  스크롤할 때마다 헤더 색이 달라집니다. 불투명 흰색으로 고정합니다.
- 제목은 **화면 정중앙**입니다. `flex-1` 에 `text-center` 를 주면
  뒤로가기 버튼만큼 밀려서, 화면을 넘길 때마다 제목이 조금씩 움직입니다.
  절대 위치로 좌우 3.5rem 을 비워 버튼과 겹치지 않게 합니다.
- 투명 헤더(`transparent`)는 **반드시 `sticky={false}`** 와 함께 씁니다.
  배경 없는 헤더가 화면에 붙어 있으면 본문이 그 밑을 지나가며 글자가 겹칩니다.

### 헤더 아래 고정 영역 — 바탕색은 본문 쪽으로

검색 바나 정렬 줄처럼 헤더 밑에 고정하는 영역입니다.
위쪽 여백은 **8px(`pt-2`) 안팎**으로 — 이보다 넓으면 헤더와 따로 노는 띠처럼 보이고,
0 이면 헤더가 그만큼 두꺼워진 것처럼 읽힙니다.

```tsx
<Header title="공연" />
<div className="bg-canvas under-header sticky z-10 px-4 pt-2 pb-3">…</div>
```

- `under-header`(styles/index.css)가 `top` 을 잡습니다.
  `top-(--spacing-header)` 만 쓰면 **노치 기기에서 헤더에 가려집니다** — 헤더는 `pt-safe` 만큼 더 큽니다.
- 바탕색은 `bg-canvas`(본문 바탕)입니다. 헤더와 같은 흰색으로 두면
  헤더가 그만큼 두꺼워진 것처럼 읽히고, 흰 입력창이 흰 면 위에 떠서 경계가 사라집니다.
- **반투명으로 두지 마세요.** 카드가 뒤로 지나가는 게 비칩니다.
- 목록이 긴 화면에서 정렬·검색은 이렇게 고정합니다. 한참 내려간 뒤에 정렬을 바꾸려고
  맨 위까지 되올라가야 하면 아무도 안 바꿉니다.

### 곡률 · 테두리 · 간격 — 화면마다 달라지면 안 됩니다

| | 값 | 어디 |
|---|---|---|
| 카드 곡률 | `rounded-2xl` (16px) | 카드·타일·큰 면 |
| 작은 면 곡률 | `rounded-xl` (12px) | 입력창·칩·아이콘 배지 |
| 테두리 | **항상 1px** `border-line` | 전부 |
| 강조 테두리 | 1px + 진한 선 (`border-line-strong` / `border-accent-600`) | 예매중·당첨 |
| 목록 간격 | `space-y-2` (8px) | 카드 목록 |
| 섹션 간격 | `space-y-6` (24px) | 섹션이 여러 개인 화면 |
| 본문 간격 | `space-y-4` (16px) | 한 가지 일만 하는 화면 |

**테두리를 2px 로 굵히지 마세요.** 목록에 여러 장 깔리면 화면이 굵은 선으로 가득 찹니다.
강조가 필요하면 두께 대신 **선을 진하게** 합니다.

> 예외 — **하나만 고르는 목록**(구역·결제수단·취소표 구역)은 `border-2` 를 항상 두고
> 고르지 않은 항목의 색만 `border-transparent` 로 둡니다.
> 고를 때 테두리가 0 → 2px 로 생기면 그 칸이 2px 씩 커져 격자가 흔들립니다.
> 두께는 고정하고 **색만** 바꾸세요.

곡률이 12·16·24px 로 섞여 있으면 스크롤할 때 화면이 들썩입니다.
큰 면은 16px 하나로 통일하세요. (카메라 뷰파인더처럼 성격이 다른 요소만 예외)

### 터치

- 누를 수 있는 것은 **최소 44×44px**. `Button` 은 `md`(44px) 이상을 쓰세요. `sm`(36px)은 카드 안 보조 버튼에만.
- 화면 **맨 아래 16px 안쪽에는 누를 것을 두지 마세요.** 엄지가 닿기 어렵고 브라우저 UI에 가립니다.
  하단 고정 영역은 `pb-[calc(2rem+env(safe-area-inset-bottom))]` 으로 여백과 노치를 함께 계산합니다.
- 서로 다른 동작의 버튼은 **8px 이상** 떨어뜨립니다. 붙어 있으면 오터치가 납니다.

### 노치·안전영역

| 위치 | 방법 |
|---|---|
| 상단 | `pt-safe` |
| 하단 (여백 없이) | `pb-safe` |
| 하단 (여백과 함께) | `pb-[calc(<여백>+env(safe-area-inset-bottom))]` |

> ⚠️ `.pb-safe` 는 `padding-bottom` 을 **덮어씁니다.** `pb-8 pb-safe` 로 같이 쓰면
> `pb-8` 이 통째로 무시되고, 노치가 없는 안드로이드에서는 여백이 0이 됩니다.

### 스크롤

- **스크롤바는 전역으로 숨겨져 있습니다.** 데스크톱에서 스크롤바가 생겼다 사라질 때마다
  폭이 바뀌어 페이지가 좌우로 밀리기 때문입니다. 가로 스크롤 영역에 `.scrollbar-none` 은 불필요합니다.
- 표·좌석맵처럼 넓은 것은 **자기 영역 안에서만** 가로 스크롤하게 하세요(`overflow-x-auto`).
  본문 전체가 좌우로 밀리면 안 됩니다.
- 검색처럼 자주 다시 쓰는 조작은 `sticky top-(--spacing-header)` 로 붙여둡니다.

### 화면을 만들기 전 확인

1. 이 화면에서 **사용자가 할 일 하나**는 무엇인가 → 그게 `primary` 버튼
2. 그 하나를 방해하는 것은 없는가 → 있으면 접거나 아래로 내린다
3. 로딩·비어 있음·에러 세 상태를 다 그렸는가 (`Loading` / `EmptyState` / `RouteBoundary`)
4. 375px 폭에서 글자가 잘리지 않는가

## 8. "AI가 만든 티" 나지 않게

생성형 도구로 UI 를 만들면 반복적으로 나오는 클리셰가 있습니다.
개별로는 멀쩡해 보이지만 한 화면에 모이면 **"어디서 본 템플릿"** 이 됩니다.

### 하지 않는 것

| 클리셰 | 왜 문제인가 | 대신 |
|---|---|---|
| **그라데이션 텍스트** (제목·이름에 보라→청록) | 가장 흔한 생성형 UI 표식 | 단색 + 굵기로 위계 |
| **배경 라디얼 글로우 블롭** | 랜딩페이지 템플릿 특유의 인상 | 단색 배경 |
| **모든 상호작용에 발광** | 중요도 구분이 사라짐 | 테두리·배경 단계로 반응 (2장) |
| **무한 반복 광택/스캔라인** | 정보가 없는데 계속 움직임 | 정지된 홀로그램 결 |
| **축포·파티클** | 두 번째부터는 방해 | 체크 아이콘 하나 |
| **`pulse` 남발** | 다 급하면 아무것도 안 급함 | 진짜 급한 것만 (타이머) |
| **모든 모서리가 `rounded-2xl` 이상** | 물렁해 보이고 위계가 없음 | 아래 반경 스케일 |
| **뱃지 도배** | 카드마다 3개씩 붙으면 안 읽힘 | 카드당 최대 1개 |
| **카드 왼쪽 세로 네온 띠** | 목록이 형광펜 칠한 것처럼 보임 | 상태는 뱃지로 |
| 느낌표 남발, "✨ 완벽해요!" 류 문구 | 과장된 톤 | 담담한 서술체 |

### 반경 스케일

크기가 다르면 반경도 달라야 합니다. 전부 같으면 위계가 사라집니다.

```
rounded-md    뱃지
rounded-lg    작은 버튼, 아이콘 칩, 포토카드
rounded-xl    카드, 기본/큰 버튼, 입력
rounded-2xl   모달·바텀시트만
rounded-full  아바타, 상태 점, 타이머
```

### 마이크로카피

- 담담한 존댓말. `~했어요` / `~해 주세요` 정도
- 느낌표는 화면당 0~1개
- 이모지는 UI 에 쓰지 않습니다 (아이콘은 lucide-react)
- 사용자가 한 일은 사실만: "예매가 완료되었습니다" (○) / "축하합니다! 예매 성공! 🎉" (×)

### 구현 사정을 화면에 적지 않습니다

우리가 어떻게 만들고 있는지는 사용자가 알 이유가 없습니다.
개발 중에 붙여둔 안내는 **화면에 남기지 말고 콘솔·README 로 보내세요.**

| ❌ 화면에 쓴 것 | ✅ 대신 |
|---|---|
| "목업 데이터로 실행 중입니다" | 아무것도 안 띄움 (콘솔에만) |
| "모의 결제 모드입니다. `VITE_TOSS_CLIENT_KEY` 에…" | 아무것도 안 띄움 |
| "기획 확정 후 추가됩니다" | "곧 열어 드릴게요" |
| "백엔드 메트릭 연동 후 구현합니다" | "준비하고 있어요" |
| 환경(`development`) · 심볼(`GRAPE`) 노출 | 안 띄움 / "캣머니" |

내부 식별자(`GRAPE`, `NFT`, `token`)는 코드에만 남기고 화면 문구는 항상 사람 말로 —
**"캣머니"**, **"포토카드"** 입니다.

### 자문

새 화면을 다 만든 뒤 스스로 물어보세요.

> **이 화면에서 움직이는 것이 몇 개인가?**
> **빛나는 것이 몇 개인가?**
>
> 둘 다 0~1개가 정상입니다.

## 9. 브랜드 — 티캣

**티캣** = 티켓 + 캣. 로고와 마스코트는 **티켓 한 장의 위쪽 두 귀퉁이를 고양이 귀로 세운** 형태입니다.
아래쪽에는 티켓 절취선이 있어서, 고양이면서 티켓인 것이 한눈에 읽힙니다.

| 자산 | 위치 | 용도 |
|---|---|---|
| 앱 아이콘 | `public/icons/logo.svg` | 브라우저 탭, PWA |
| `<CatMascot>` | `shared/components/ui/CatMascot.tsx` | 빈 상태, 완료 화면, 에러 화면 |
| `<Logo>` | 같은 파일 | 마크 + 워드마크 (로그인/가입 상단) |

### 표정 (mood)

| mood | 언제 |
|---|---|
| `neutral` | 기본 (로그인 유도 카드 등) |
| `happy` | 예매 완료, 당첨 |
| `sad` | 빈 목록, 404, 에러 화면 |
| `sleep` | 준비 중인 기능 |

```tsx
<EmptyState mood="sad" title="예매한 티켓이 없어요" />   // 아이콘 대신 마스코트
<EmptyState icon={Search} title="검색 결과가 없어요" />   // 아이콘을 주면 아이콘
```

새 표정이 필요하면 `CatMascot.tsx` 의 `Face` 함수에 분기 하나만 추가하세요.

이미지가 아니라 SVG 라 번들이 늘지 않고, 색이 브랜드 토큰을 따라갑니다.
**마스코트에 3D·그라데이션·반짝임을 붙이지 마세요** (8장).
빈 화면·완료 화면처럼 **여백이 넉넉한 곳에만** 씁니다. 목록 항목마다 넣으면 유치해집니다.

## 10. 홈 히어로 — 검정/하양 경계

홈은 상단이 짙은 강조색 면(`.surface-strong`), 아래가 흰 배경이고 **배너가 그 경계에 걸쳐** 내려옵니다.

```
┌───────────────┐
│               │  ← 노치 위 여백 0.75rem
│ ███ 검정 ████ │  상단바 (로고 · 검색)
│  ┌─────────┐  │
│  │  배너   │  │  4:3
│  ├ ─ ─ ─ ─ ┤  │  ← 경계 = 배너 높이의 90%
│  └─────────┘  │
│ ░░░ 하양 ░░░░ │  바로가기 · 목록
└───────────────┘
```

### 경계는 JS 로 재지 않습니다

`styles/index.css` 의 `:root` 에 배너 크기를 CSS 로 계산해 둡니다.

```css
--banner-width: calc(min(100vw, 40rem) - 2rem);  /* 레이아웃 최대폭 - 좌우 여백 */
--banner-height: calc(var(--banner-width) * 3 / 4);
```

검정 배경판의 높이는 이 값으로 구합니다.

```
env(safe-area-inset-top) + 헤더 위 여백 + 헤더 높이 + 배너 위 여백 + 배너 높이 × 0.9
      (노치)              0.75rem       3rem       0.5rem
```

⚠️ **헤더 여백이나 배너 위 여백을 바꾸면 이 식도 같이 고쳐야 합니다.**
한쪽만 바꾸면 경계가 90% 지점에서 벗어나 배너가 어정쩡하게 걸칩니다.

`ResizeObserver` 나 `useState` 로 높이를 재면 첫 렌더에 경계가 잘못 그려지고
회전·주소창 변화 때마다 깜빡입니다. CSS 로만 두면 그런 일이 없습니다.

### ⚠️ 배너 비율을 바꾸면 두 곳을 함께 고쳐야 합니다

1. `BannerCarousel` 의 `aspect-[4/3]`
2. `--banner-height` 의 `* 3 / 4`

한쪽만 바꾸면 경계가 배너 위/아래로 어긋납니다.

### 홈의 순서는 고정입니다

```
헤더(서비스명 · 검색 아이콘)
  ↓
캐러셀 (4:3, 검정/하양 경계에 걸침)
  ↓
바로가기 **5칸 한 줄** — 전부 "내 것" (내 티켓 · 취소표 · 캣머니 · 내 포카 · 마이)
  ↓
진행 중인 티켓팅 — **가로 레일**
  ↓
새로 올라온 포토카드 — **가로 레일** (속도를 다르게)
```

공연·포카 **탐색**은 바로가기에 두지 않습니다. 하단 탭에 이미 있어서
같은 목적지가 한 화면에 두 번 나옵니다.

두 레일의 **흐르는 속도는 서로 달라야** 합니다(15 / 9 px/s).
같으면 두 줄이 한 덩어리처럼 같이 밀려서 화면 전체가 흔들리는 것처럼 보입니다.

- 검색은 헤더에 **아이콘 하나**로 둡니다. 입력창을 헤더에 넣으면 로고 자리가 좁아집니다.
  누르면 **통합 검색 화면**(`ROUTES.SEARCH`)으로 갑니다 — 공연 목록으로 보내지 마세요.
- 로고는 마스코트만 크게(`markSize`) 쓰고 워드마크는 그대로 둡니다.
  `size` 를 함께 키우면 글자가 헤더 높이를 넘습니다.
- 바로가기 라벨은 **4글자 이하**. 한 칸이 62px 라 넘치면 두 줄로 접힙니다.
- 로그인 전에는 바로가기 아래에 로그인 카드가 붙습니다.
- **얼굴 등록으로 보낼 때는 `state: { from: location }` 을 같이 넘깁니다.**
  안 넘기면 등록을 마친 뒤 마이페이지로 가버려서, 홈에서 눌렀는데 딴 데 놓입니다.

### 검색은 한 화면에서 둘 다 찾습니다

`SearchPage` 하나가 **공연과 포토카드를 함께** 찾습니다.
"공연 검색 / 포카 검색" 으로 나누면 잘못 고른 사람은 "없다"고 판단하고 나갑니다.

- 입력창은 **헤더 안**에 둡니다. 검색 화면의 주인공이 입력창인데
  제목("검색")을 따로 두면 정작 쳐야 할 곳이 한 줄 아래로 밀립니다.
- 조회는 `useDebouncedValue` 로 **잠잠해진 뒤에** 합니다.
  글자마다 조회하면 다섯 글자에 요청이 다섯 번 나가고, 응답 순서가 뒤바뀌면
  이전 키워드의 결과가 화면에 남습니다.
- 각 종류는 6건까지만. 더 있으면 "전체 N건" 으로 해당 탭에 넘깁니다.

### 마이페이지 프로필 — 경계는 카드 **중앙**

홈과 같은 검정/하양 구조를 프로필 카드에도 씁니다. 다만 경계가 카드 중앙입니다.

```tsx
<Header title="MY" transparent sticky={false} className="relative z-10 text-white" />
<div className="pt-3">
  <div className="relative px-4">      {/* 이 컨테이너는 카드 하나만 감쌉니다 */}
    <div aria-hidden className="surface-strong absolute inset-x-0 bottom-1/2" style={{ top: '…' }} />
    <div className="surface shadow-card relative rounded-2xl pt-11">…</div>
  </div>
</div>
```

⚠️ `bottom-1/2` 는 **컨테이너 높이의 50%** 입니다. 컨테이너가 카드 하나만 감싸고 있어야
그 50% 가 카드 중앙이 됩니다. 여백(`pt-3`)을 이 안에 넣으면 경계가 그만큼 위로 밀립니다.
그래서 여백은 **바깥** 래퍼에 둡니다.

얼굴 아이콘은 카드 위쪽 테두리에 **절반만 걸칩니다**(`-top-7` = size-14 의 절반).
검정 위에 놓이는 절반이 묻히지 않게 `border-4 border-surface-1` 로 흰 테를 둡니다.

### 포카 마켓 — 구매 / 판매는 **한 화면**

`Segmented` 토글로 방향만 바꿉니다.

| 탭 | 무엇 |
|---|---|
| 구매 | 남들이 올린 카드 (마켓 조회 + 정렬) |
| 판매 | 내가 가진 카드. 눌러 들어가면 상세에서 가격을 매겨 올립니다 |

화면을 둘로 나누면 "내 카드 팔려면 어디 가지?" 를 매번 찾게 됩니다.

- 정렬은 **구매 탭에만**. 내 카드는 몇 장뿐이라 정렬할 게 없습니다 — 대신 장수를 보여줍니다.
- 내 카드 검색은 서버를 다시 부르지 않고 **화면에서 거릅니다**(개수가 적음).
- 판매 탭 카드에는 가격 대신 판매 상태(판매 중 / 보관 중)를 띄웁니다.

#### 구매 안에 상점 · 경매 — 두 번째 층은 **글자 탭**

알약은 구매·판매 **두 칸 그대로**입니다. 상점과 경매는 둘 다 "남의 카드를 사는 방법" 이고
판매는 "내 카드 목록" 이라, 셋을 한 줄에 놓으면 성격이 다른 것이 같은 층으로 읽힙니다.

```
[  구매  |  판매  ]            ← Segmented (알약)
[ 🔍 도안명, 공연명으로 검색 ]
 상점  경매        💰8,400  정렬⌄   ← 글자 탭이 기존 줄 왼쪽에
```

- **알약 아래에 알약을 쌓지 마세요.** 둘이 서로 경쟁해서 어느 쪽이 지금 화면을
  정하는지 알 수 없습니다. 두 번째 층은 선택된 쪽만 진하게(`font-extrabold`),
  나머지는 흐리게(`text-subtle`) 둡니다. 밑줄·테두리·알약을 쓰지 않습니다.
- 줄 수는 **세 줄 그대로**입니다. 줄이 늘면 카드가 그만큼 아래로 밀립니다.
- 정렬 옵션이 다릅니다 — 상점은 최신·가격순, 경매는 **마감 임박순이 기본**입니다.
  경매에서 지금 봐야 하는 건 곧 끝나는 것입니다.
- 검색어는 상점·경매가 **공유**합니다. 같은 말을 두 번 치게 하지 않습니다.
- 경매 카드는 포카 카드와 같은 틀이고 셋째 줄만 다릅니다 —
  현재가(가장 큼) 아래 **남은 시간과 입찰 수** 한 줄. 즉시구매가 있으면 카드 위에 작은 뱃지.

### 포토카드에는 등급이 없습니다

NORMAL/RARE/SPECIAL 같은 **등급표를 두지 않습니다.**
카드의 가치는 등급 라벨이 아니라 **어떤 공연의 어떤 순간인지**와 가격으로 정해집니다.
등급을 붙이면 색이 세 개 더 필요해지고, 낮은 등급 카드는 아무도 안 봅니다.

마켓 카드는 회색 타일 위에 아트를 **여백을 두고** 올립니다.
카드가 가장자리까지 꽉 차면 실물 카드가 아니라 배너처럼 보입니다.

**타일에 테두리를 두르지 마세요.** 격자로 여러 장 깔리면 선끼리 겹쳐 지저분해집니다.
면과 면 사이의 흰 여백이 곧 구분선입니다. 글자는 셋뿐 — 이름 · 공연 · 가격,
그중 **가격이 가장 큽니다**(17px).

### 목록이 짧으면 가로 레일로

진행 중인 티켓팅처럼 **몇 개만 보여주고 넘기는** 목록은 세로로 쌓지 않습니다.
세로로 쌓으면 두 장만 있어도 화면이 다 차서 아래 내용이 밀려납니다.

```
-mx-4 로 화면 끝까지 흐르게 → 안쪽 px-4 로 첫 카드를 본문에 맞춤
snap-x snap-mandatory + scroll-px-4
```

다음 카드가 화면 오른쪽에 **살짝 걸쳐 보여야** "더 있다"는 게 읽힙니다.
카드 폭은 화면의 40% 미만(현재 136px)으로 잡으세요.

### 짙은 면 안의 글자

`.surface-strong`(강조색 짙은 면)을 쓰면 글자색이 흰색으로 바뀝니다.
그 안에서는 밝기 규칙이 반대입니다.

- 마스코트·로고: `<Logo invert />` / `<CatMascot invert />`
- 테두리: `border-white/25`
- 보조 글자: `text-white/70`

## 11. 배포

```bash
npm run build      # → dist/
npm run preview    # 빌드 결과를 로컬에서 그대로 확인 (배포 전 필수)
```

`npm run dev` 로 잘 돌아도 배포본이 깨질 수 있습니다. **배포 전에 반드시 `npm run preview` 로 확인**하세요.

### 백엔드가 없는 동안 — 배포본도 목업으로 돕니다

`.env.production` 의 `VITE_USE_MOCK=true` 입니다.

이걸 `false` 로 두면 **배포한 사이트에서 로그인·공연 조회가 전부 실패합니다.**
개발 서버의 `/api` 프록시는 배포 환경에 없어서, `/api/...` 요청이 정적 호스팅으로 가
`index.html` 이 돌아오기 때문입니다.

백엔드가 붙으면:

1. `.env.production` 의 `VITE_USE_MOCK=false`
2. `VITE_API_BASE_URL` 을 실제 API 주소로 (같은 도메인이면 `/api` 유지)
3. `src/mocks/` 폴더 삭제 + `main.tsx` 의 `setupMocks()` 블록 삭제

> 목업이 켜진 배포본은 **데모**입니다. 새로고침하면 데이터가 초기화되고,
> 브라우저마다 데이터가 따로 갑니다(각자 메모리에서 도니까요).

### ⚠️ SPA 폴백 설정 — 없으면 새로고침이 404

이 앱은 주소를 브라우저가 처리합니다. 서버는 `/login` 이라는 파일을 갖고 있지 않으므로,
그 주소를 직접 열거나 새로고침하면 **404** 가 납니다. 호스팅마다 폴백을 설정해야 합니다.

| 호스팅 | 설정 | 상태 |
|---|---|---|
| Netlify / Cloudflare Pages | `public/_redirects` | ✅ 포함됨 |
| Vercel | `vercel.json` | ✅ 포함됨 |
| GitHub Pages | `npm run build:pages` (404.html 생성) | ✅ 스크립트 있음 |
| nginx / S3+CloudFront | 아래 참고 | ⚠️ 직접 설정 |

**nginx**

```nginx
server {
  root /var/www/tikat;

  # 정적 파일이 있으면 그대로, 없으면 index.html (SPA 라우팅)
  location / {
    try_files $uri $uri/ /index.html;
  }

  # 서비스워커·매니페스트는 캐시하지 않습니다.
  # 캐시되면 새 배포가 사용자에게 며칠씩 안 갑니다.
  location = /sw.js {
    add_header Cache-Control "no-cache";
  }
  location = /manifest.webmanifest {
    add_header Cache-Control "no-cache";
  }

  # 해시가 붙은 에셋은 오래 캐시해도 안전합니다.
  location /assets/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
  }
}
```

**S3 + CloudFront** — CloudFront 오류 페이지에서 403·404 를 `/index.html` (200) 로 응답하도록 설정합니다.

### HTTPS 가 필요한 기능

| 기능 | 이유 |
|---|---|
| 얼굴 등록 (카메라) | `getUserMedia` 는 HTTPS 또는 localhost 에서만 동작 |
| PWA 설치 | 서비스워커가 HTTPS 필요 |
| 결제창 | 대부분의 PG 가 HTTPS 를 요구 |

`http://` 로 배포하면 이 세 가지가 조용히 실패합니다.

## 12. 결제 (토스페이먼츠)

프론트가 하는 일은 **결제창 호출과 인증까지**입니다. 승인은 백엔드가 합니다.

```
① prepare   POST /payments/prepare        서버가 주문 생성 + 금액·orderId 확정
        ↓
② 결제위젯   widgets.requestPayment()      사용자 인증 (카드·간편결제)
        ↓  성공하면 successUrl 로 페이지 이동
③ confirm   POST /payments/confirm        백엔드가 토스 승인 API 호출 → 티켓 발급
```

### 결제위젯은 시트에 담습니다

`renderPaymentMethods()` 가 만드는 UI 는 500px 가까이 됩니다.
결제 페이지 본문에 그대로 붙이면 금액·약관·버튼이 저 아래로 밀리고,
스크롤 도중 위젯 iframe 위를 지나가 누르기도 어려워집니다.

**결제할 때만 시트로 덮습니다** (`TossPaymentSheet`) — 새 창처럼 동작하고
본문 레이아웃은 짧게 유지됩니다. 시트 본문은 스크롤되고 결제 버튼은 하단에 고정입니다.
결제가 진행되는 동안에는 닫히지 않습니다(`dismissible={false}`) —
중간에 닫으면 사용자는 취소된 줄 알지만 실제로는 창이 떠 있을 수 있습니다.

개별 연동 키(`test_ck_...`)를 쓰면 토스가 **진짜 새 창**을 띄우므로 시트는 뜨지 않습니다.

### 결제위젯은 팝업이 아니라 페이지 안에 들어옵니다

`renderPaymentMethods()` / `renderAgreement()` 가 지정한 자리에 토스의 UI 를 삽입합니다.
그래서 **결제 버튼을 누르기 전에 미리 그려둬야** 합니다. (`useTossWidget`)
버튼을 누르는 순간 만들 수 없습니다.

### ⚠️ 토스는 성공 시 "항상" 리디렉션입니다

`successUrl` 을 주면 인증 성공 후 그 주소로 **페이지가 이동**합니다.
데스크톱·모바일 구분 없이 성공 결과는 리디렉션으로만 돌아옵니다.

```
successUrl?paymentKey=...&orderId=...&amount=...
failUrl?code=...&message=...&orderId=...
```

그래서 결제 결과 라우트(`BOOKING_PAYMENT_RESULT`)가 **필수**입니다.
그 라우트는 **로그인 가드만** 통과하면 되도록 두세요. 얼굴 등록·OTP 가드를 걸면
결제는 끝났는데 승인 요청을 못 보내 **"돈은 빠졌는데 티켓이 없는"** 사고가 납니다.

예매 플로우 스토어(`bookingStore`)를 sessionStorage 에 유지하는 것도 이 때문입니다.
메모리에만 두면 리디렉션 복귀 때 선점·멱등키가 사라집니다.

### 금액은 서버가 정하고, 서버가 다시 검증합니다

프론트가 계산한 금액을 결제창에 넣고 그대로 믿으면 **1원 결제**를 만들 수 있습니다.
화면은 금액을 *보여주기만* 하고, 결제창에 넣는 값은 `prepare` 응답을 그대로 전달합니다.

승인 단계에서 프론트가 보내는 `amount` 는 **주소창(successUrl 쿼리)에서 온 값**이라
사용자가 고칠 수 있습니다. 백엔드는 이 값을 믿지 말고 `prepare` 때 저장한 금액과
비교한 뒤, **저장된 금액으로** 승인해야 합니다.

```
POST https://api.tosspayments.com/v1/payments/confirm
Authorization: Basic base64(SECRET_KEY + ':')
{ paymentKey, orderId, amount }   ← amount 는 서버가 저장한 값
```

시크릿 키(`test_sk_...`)는 **절대 프론트에 두지 않습니다.**

### 토스 규격 — 어기면 결제창이 안 열립니다

| 항목 | 규격 |
|---|---|
| `orderId` | **6~64자, 영문·숫자·`-`·`_` 만.** 한글·공백 불가 |
| `orderName` | 100자 이내 |
| `customerMobilePhone` | 숫자만 (하이픈 불가) |
| `amount` | 정수 (원 단위) |

서버가 `orderId` 를 만들 때 이 규칙을 지켜야 합니다. (목업은 `tikat-{timestamp}-{rand}`)

### 결제수단 — 지금은 둘뿐입니다

| 화면 표시 | 실제 동작 |
|---|---|
| 간편결제 (토스) | 토스 통합결제창 — 카드·토스페이·네이버페이가 한 창에 (`method: 'CARD'` + `flowMode: 'DEFAULT'`) |
| 캣머니로 결제 | **PG 를 타지 않습니다.** 서버가 잔액을 차감하고 바로 티켓 발급 |

카드·계좌이체·가상계좌는 화면에서 뺐습니다.
(가상계좌는 입금 웹훅이 있어야 완료라서 시연에 맞지 않습니다)

**캣머니 결제에는 결제창도 리디렉션도 없습니다.** `prepare → confirm` 두 번이면 끝입니다.
화면에 보이는 캣머니 개수는 어림값이고, **차감량은 서버가 다시 계산**합니다.
프론트가 계산한 숫자를 그대로 차감하면 공짜 티켓이 나옵니다.

### 캣머니로 낼 거면 **줄마다** 캣머니로

결제 금액표에서 위는 원, 맨 아래만 캣머니면 "그래서 얼마가 나가는데?" 를 암산하게 됩니다.
수단이 캣머니면 티켓 금액·수수료·총액을 **전부** `formatPoints()` 로 씁니다.

⚠️ 각 줄을 따로 `toPoints()` 하지 마세요. 줄마다 올림이 붙어 **합이 총액과 어긋납니다.**
한 줄은 총액에서 빼서 구하세요.

```ts
const ticketPoints = toPoints(total);
const feePoints = pointsNeeded - ticketPoints;   // ← 따로 올림하지 않음
```

### 수령인은 고칠 수 없습니다

예매 확인 단계의 "티켓 받을 사람" 은 **읽는 줄**입니다(입력창 아님).
열어 두면 남의 아이디를 넣어 넘기는 길이 생기고, 그게 곧 암표입니다.
입력창처럼 보이는데 안 고쳐지면 더 답답하므로, 아예 회색 면에 얹은 텍스트로 보여줍니다.

### 선점 타이머는 테두리 없이 채운 면으로

예매 중 **가장 먼저 봐야 하는 숫자**입니다. 헤더 옆의 작은 알약에 테두리까지 있으면
시간보다 테두리가 먼저 보입니다. 평소 `bg-accent-700`(진행 중), 1분 미만이면 `bg-danger` + 맥박.

### 실제 테스트 결제 켜기 — 이미 켜져 있습니다

토스가 **가입 없이 쓰라고 공개한 문서용 테스트 키**가 `.env` 에 들어 있습니다.
그대로 실행하면 진짜 토스 결제 UI 가 뜨고, 결제하기를 누르면 `toss.im` 으로 넘어갑니다.

```bash
VITE_TOSS_CLIENT_KEY=test_gck_docs_Ovk5rk1EwkEbP0W43n07xlzm
```

### ⚠️ 클라이언트 키는 두 종류이고, 서로 호환되지 않습니다

| 키 | 짝이 되는 SDK | 화면 |
|---|---|---|
| `test_ck_...` (API 개별 연동 키) | `tossPayments.payment()` | 팝업 결제창 |
| `test_gck_...` (**결제위젯** 연동 키) | `tossPayments.widgets()` | 페이지에 삽입 |

잘못 짝지으면 결제가 아예 시작되지 않고 이 메시지가 뜹니다.

```
API 개별 연동 키의 클라이언트 키로 SDK를 연동해주세요. 결제위젯 연동 키는 지원하지 않습니다.
```

공개된 문서용 키가 **위젯 키뿐**이라 이 프로젝트는 위젯을 씁니다.
개별 연동 키(`test_ck_...`)를 발급받아 팝업 결제창으로 바꾸려면
`paymentGateway.ts` 의 `mountWidget` / `requestPayment` 만 고치면 됩니다.

### 🔴 시크릿 키는 절대 프론트에 두지 않습니다

문서에는 시크릿 키(`test_gsk_...`)도 같이 적혀 있지만, **승인 API 전용**이고
**백엔드 환경변수**에만 둡니다. `VITE_` 로 시작하는 값은 빌드 시 번들에 그대로 박혀
브라우저 개발자도구에서 누구나 읽을 수 있습니다. 프론트에 두면
아무나 그 상점의 결제를 승인·취소할 수 있습니다.

| 모드 (`VITE_PAYMENT_MODE`) | 동작 |
|---|---|
| `auto` (기본) | 키가 있으면 실제 위젯, 없으면 모의 결제 |
| `toss` | 항상 실제 위젯 (키 없으면 안내 메시지) |
| `mock` | 항상 모의 결제 (확인 창) |

> ⚠️ 결제 인증은 **HTTPS 에서만** 정상 동작합니다. (localhost 는 예외)

### 폴더 구조 — PG 의존은 한곳에

```
features/payment/
├── api/
│   ├── paymentGateway.ts   토스 SDK 호출 (auto/mock/toss) ← PG 교체 시 여기만
│   └── paymentApi.ts       우리 백엔드 (prepare / confirm)
├── model/
│   ├── payment.types.ts
│   └── payment.model.ts    취소인지 실패인지 판별
└── hooks/
    ├── usePayment.ts       ①②③ 오케스트레이션
    ├── useTossWidget.ts    위젯을 화면에 그리기
    └── usePaymentResult.ts 리디렉션 복귀 처리
```

화면은 `usePayment` 만 압니다. SDK 는 동적 import 라서 모의 결제 모드에서는 로드되지 않습니다.

### 취소는 에러가 아닙니다

사용자가 결제창을 닫은 것을 실패로 처리하면 "결제 실패했습니다" 토스트가 떠서
문제가 생긴 줄 알고 불안해합니다. `payment.model.ts` 의 `toPaymentFailure` 가
토스의 취소 코드(`PAY_PROCESS_CANCELED` 등)를 판별하니, 취소면 **조용히 되돌아갑니다.**

### 진행 단계를 보여주세요

결제창이 열린 동안 사용자는 뭘 기다리는지 모릅니다.
`usePayment` 의 `stage` 를 버튼 문구로 씁니다.

| stage | 버튼 문구 |
|---|---|
| `preparing` | 주문 확인 중 |
| `authenticating` | 결제창에서 진행해 주세요 |
| `confirming` | 결제 승인 중 |
